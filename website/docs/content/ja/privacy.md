## ノートと手元のデータ

irori はデスクトップアプリです。ノートと資料は開いたフォルダにあり、編集もそこに保存されます。Git のリモートやクラウドフォルダを接続すると、設定した転送が加わります。ローカルの hibachi を開くだけで、ファイルが irori のアカウントにアップロードされることはありません。

この端末のアプリデータには、設定、フォルダ・アカウント情報、検索・グラフ用の索引、AI の会話記録、出典の確認用に保持した資料のコピーが含まれます。保持したコピーには Google Drive のファイル内容が含まれる場合があります。元のファイルを削除しても、保持したコピーがすべて自動的に消えるわけではありません。

## Google Drive の権限

Google へのログインはシステムのブラウザで行います。irori は端末上の rclone と OAuth のアクセストークン・更新トークンを使って Drive に接続します。Google のパスワードを irori に入力することはありません。

Google へのログイン、接続先フォルダの一覧、Drive のマウントを初めて行う前に、irori は Drive のデータ利用説明への確認を求めます。確認はこの端末に記録され、リセットまたは説明の版が変わるまで使われます。Google が表示する権限の許可とは別です。

現在の接続は、既存フォルダの一覧とファイルの閲覧・作成・変更・削除のために、Drive 全体の権限 `https://www.googleapis.com/auth/drive` を求めます。この許可は、アカウントがアクセスできる Drive のファイルが対象で、irori で選んだフォルダより広い範囲です。フォルダの選択は接続の作業場所を決めます。irori の読み取り専用設定に切り替えても、アカウントが持つ OAuth の許可範囲は狭くなりません。

Drive のファイル内容、名前、識別子、接続情報は、資料の一覧・表示・編集・アップロードに使われます。読み込んだファイルや送信待ちの変更は、切断や終了の後もローカルキャッシュに残る場合があります。接続と送信待ちの操作は [Google Drive](drive.md) を参照してください。

## AI などへの送信

[AI agent](agents.md) を開始すると、irori は依頼と関連する文脈を選択したローカル CLI に渡します。アクセス設定と指示によっては、CLI がノートや接続した Drive のファイルを読み、その内容、ツールの結果、会話の文脈を外部のモデル提供者に送ります。Drive の接続だけで AI への依頼が始まることはありません。

CLI ごとの初回実行前に、irori は AI への送信と履歴の説明への確認を求めます。送信待ちの仕事、ルーティンの AI ステップ、agent 間で委任された仕事も対象です。ターミナルとルーティンには、アクセス可能なファイルを読み外部サービスに通信できるプログラムについての確認が別にあります。これらは説明の確認であり、個々のツール実行の承認や通信の制限、提供者の扱いが Google のルールに適合する保証ではありません。

CLI とモデル提供者は、利用者自身の認証とアカウント設定を使います。サーバーでの処理、保持期間、人による閲覧、モデル学習への利用は、それぞれの利用条件で決まります。機密情報へのアクセスを許可する前に、条件と設定を確認してください。汎用モデルの学習など、[Google Workspace API のユーザーデータポリシー](https://developers.google.com/workspace/workspace-api-user-data-developer-policy) に反する利用をするサービスに Drive のデータを送らないでください。irori で会話を停止・削除しても、提供者が受け取ったコピーは消えません。

Git の同期は、設定したリモートにリポジトリの内容を送ります。更新確認とダウンロードは GitHub に接続します。このドキュメントサイトは GitHub Pages 上にあり、閲覧時には通常のウェブリクエストがホストに送られます。ドキュメントの検索はブラウザ内で動き、選んだテーマはローカルストレージに保存されます。

## 保存と保護

ノート、Drive のキャッシュ、保持した資料、会話履歴はローカルのファイルです。irori 自体がこれらをすべて暗号化するわけではありません。OS のディスク暗号化とアカウント保護を使い、バックアップの扱いも確認してください。CLI に許可するアクセスには、これらのファイルが含まれる場合があります。

Drive の認証情報は編集するノートとは別に保存されます。アカウントを削除すると rclone に保存した認証情報を削除しますが、フォルダを一つ切断するだけではアカウントの削除や Google 側の許可取り消しにはなりません。アプリデータのフォルダ、認証情報、伏せていないログを公開 Issue に載せないでください。

rclone の認証設定ファイルは暗号化し、その暗号化キーを OS の安全な保存先で保護します。既存の平文の設定はクラウドサービスの開始時に移行し、安全な保存先が使えない場合は Google に接続できません。この保護は認証設定が対象で、上で説明したキャッシュ、資料のコピー、ノート、会話ファイル全体には及びません。

## 切断と削除

**設定 → データ利用を確認し直す** は確認の記録を消し、次の接続・実行前に再確認します。実行中の仕事は停止せず、Google の許可を取り消したり、保存したデータを削除したりする操作ではありません。

1. Drive を切断する前に送信待ちを確認します。残した変更は再接続で送信される場合があるため、必要な変更を保存する前にキャッシュを削除しないでください。
2. アカウントを irori から削除する前に、そのアカウントを使うフォルダの接続を外します。
3. [Google アカウントのサードパーティ接続](https://myaccount.google.com/connections)で irori の許可を取り消すと、Google 側の許可を撤回できます。端末にあるファイルのコピーは消えません。
4. [履歴](conversations.md)から会話を削除すると、irori が保存した会話を削除します。CLI 自身の履歴と提供者のサーバーにあるコピーは、それぞれ別の操作が必要です。

Drive の切断、会話の削除、hibachi の削除、irori のアンインストールだけで、すべてのデータが消えるわけではありません。キャッシュ、保持した資料、CLI の履歴、Git のリモート、バックアップをまとめて消す操作はありません。端末のデータをすべて削除する場合は、必要なノートと未送信の編集を先に保全し、irori と CLI を閉じ、それぞれのアプリデータのフォルダとバックアップを確認してから削除してください。Google とモデル提供者が保持するコピーは、それぞれのサービスの操作を使います。
