## できること

vault はこのコンピューターの外にも置けます。`ssh` でつながる Linux マシン（SSH ホスト）の vault を、ほかの vault と同じワークスペースに並べて表示できます。

その vault のエージェントはホストで動きます。コードを動かすのは別のマシン、vault との会話はここ、という分け方ができます。いまの段階では、SSH ホストの vault は**表示のみ**で、ウィンドウからは変更しません。

## 始める前に

- irori はこのコンピューターの `ssh` を、その鍵・エージェント・設定のまま使います。パスワード、パスフレーズ、ホスト鍵の確認には答えられないため、先にターミナルで `ssh 接続先` がそれだけでつながることを確かめてください。
- ホストは Linux（x64 または arm64）で、glibc 2.28 以降が必要です。
- vault のエージェントはホストで動きます。使う CLI（Claude Code、Codex など）をホストにインストールし、ログインしておいてください。

最初の接続で、irori は自分のファイルをホストの `~/.irori-host` に置きます。動かすための Node（公式ビルド、約 55 MB）はこのコンピューターがダウンロードして接続越しに送るため、ホストからインターネットにつながる必要はありません。システム全体には何もインストールしません。

## SSH ホストを追加する

1. **設定 › vault の場所 › SSH ホスト** を開きます。
2. **SSH ホストを追加** を押します。
3. **名前** と **接続先** を入力します。接続先は `ssh` のあとに打つもの、つまり ssh 設定の Host 名か `ユーザー@ホスト` です。必要なら **ポート（省略可）** も入力し、**追加** を押します。

一覧の **接続** でつなぎ、**編集** で名前や接続先を直し、**削除** で一覧から消します。SSH ホストはこのコンピューターだけの記録で、[GitHub に保存する環境](settings.md)には含まれません。

## vault を追加する

ホストの行の **vault を追加** を押すと、ホストのフォルダをたどるダイアログが開きます。起動画面の **SSH ホストから**、または vault を追加するダイアログの **SSH ホスト** からも始められます。

フォルダを選ぶか **ホストのフォルダのパス** に `/` で始まるパスを入力し、**vault にする** を押します。まだ vault でないフォルダには、ほかのフォルダと同じように `.irori/scope.json` を作り、`.gitignore` に `/contents/` の行を加えます。このコンピューターや別のホストですでに登録した vault は、二重には登録できません。

追加した vault は、表示中のワークスペースに入ります。

## 表示されるもの

ファイル、ノート、検索、バックリンク、コメント、プロパティ、オントロジー、Git の状態・履歴・差分は、ホストから読んで表示します。ノートは読み取り専用で開きます。

vault のパネルにはホストの名前が出ます。ホストにつながらないときは **接続** を押してつなぎ直します。vault のメニューの **一覧から外す** は、このコンピューターの一覧から外すだけで、ホストのフォルダはそのまま残ります。

## エージェントに任せる

SSH ホストの vault には、vault agent の指示欄の代わりに案内が出ます。[irori mode](irori-mode.md) で irori agent に依頼してください。

irori agent が仕事を任せると、その vault のエージェントは**ホストで**、vault の中で動きます。途中の手順や許可の確認は irori agent の会話に出て、ここで答えます。irori agent を止めると、ホストの実行も止まります。

irori agent は必要なときに `irori ls`・`irori read`・`irori search` でその vault を読み、`irori send` でファイルを vault の作業フォルダに渡します。任せる仕事の本文は30,000文字までで、それより長い資料はこの方法で渡します。

作業中に接続が切れても、ホストでの実行は続きます。報告はホストで1日待ち、接続が戻ったときに irori が受け取ります。実行も報告の待ちもなく、irori もつながっていない状態が15分続くと、irori がホストで起動したものは自動で終わります。

## 知っておくこと

- irori agent がホストに送った文章（任せた仕事や `irori send` のファイル）は、ホストに残り、そのホストの管理者が読めます。ホストでの CLI の記録も同じです。
- いまは対応していないもの：SSH ホストの vault の編集、その vault のエージェントとの直接の会話、ターミナル、接続フォルダ、ルーチン。
- 別のコンピューターで環境を復元すると、そのコンピューターに SSH ホストを追加するまで、この vault は使えない状態で表示されます。
