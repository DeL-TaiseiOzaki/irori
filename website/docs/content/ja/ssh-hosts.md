## できること

vault はこのコンピューターの外にも置けます。`ssh` でつながる Linux マシン（SSH ホスト）の vault を、ほかの vault と同じワークスペースに並べて表示できます。

その vault のエージェントはホストで動きます。コードを動かすのは別のマシン、エージェントやノートとの会話はここ、という分け方ができます。ターミナルもホストで開きます。いまの段階では、SSH ホストの vault の中身は**表示のみ**で、エクスプローラーやエディターからは変更しません。

## 始める前に

- irori はこのコンピューターの `ssh` を、その鍵・エージェント・設定のまま使います。踏み台（`ProxyJump`）も、ssh の設定に書いてあればそのまま通ります。接続のときに `ssh` が入力を求めたら、[irori のウィンドウで答えられます](#section-4)。
- ホストは Linux（x64 または arm64）で、glibc 2.28 以降が必要です。
- vault のエージェントはホストで動きます。使う CLI（Claude Code、Codex など）をホストにインストールし、ログインしておいてください。

最初の接続で、irori は自分のファイルをホストの `~/.irori-host` に置きます。動かすための Node（公式ビルド、約 55 MB）はこのコンピューターがダウンロードして接続越しに送るため、ホストからインターネットにつながる必要はありません。システム全体には何もインストールしません。

## SSH ホストを追加する

**設定 → vault の場所 → SSH ホスト** を開きます。

**ssh の設定に書いてあるホスト。** VS Code の Remote-SSH と同じように、あなたの ssh の設定にあるホストが **ssh の設定にあるホスト** に並びます。ホストの **追加** を押すと、その名前で追加されます。ホストが多いときは、一覧の上の欄に入力すると、名前・アドレス・ユーザー名で絞り込めます。

irori が読むのは `~/.ssh/config`、そこから Include されるファイル、システムの設定ファイルで、これらには何も書き込みません。接続のたびに `ssh` が設定を読むので、あとで設定を書き換えても irori 側の変更は要りません。一覧に並ぶものは次のとおりです。

- `Host` の行に書かれた名前を1つずつ。`ssh` が実際に使うアドレス・ユーザー名・ポートを添えます。`Host *` のようなパターンで決めた設定も反映します。
- `*.example.com` や `!name` のようなパターンは並びません。つなぎ方の指定で、ホストそのものではないためです。パターンだけに当てはまるホストは、接続先を入力して追加してください。
- `Match` の行にしか出てこないホストは並びません。
- `Include` で指定したファイルは、`ssh` と同じ読み方をします。`Host` の行より下に書いた `Include` はそのブロックに属します。`ssh` はそのブロックに当てはまるホストのためにだけファイルを読み、中に書かれたほかのホストは使いません。`Include` はファイルの先頭に書いてください。

**それ以外のホスト。** **接続先を入力して追加** を押し、**名前** と **接続先**（`ssh` のあとに打つもの。`ユーザー@ホスト` か、ssh 設定の Host 名）を入力します。必要なら **ポート（省略可）** も入力し、**追加** を押します。

一覧の **接続** でつなぎ、**編集** で名前や接続先を直し、**削除** で一覧から消します。SSH ホストはこのコンピューターだけの記録で、[GitHub に保存する環境](settings.md#section-6)には含まれません。

## パスワードや検証コードを求められたら

接続のとき、`ssh` が入力を求めることがあります。irori はその質問を **（ホスト名）に接続** というダイアログに、`ssh` の文面のまま表示します。

- **パスワード・鍵のパスフレーズ・検証コード（2 段階認証）**：入力して **送信** を押します。入力は伏せ字で、**入力を表示** にチェックすると見えます。入力した内容は `ssh` に渡すだけで、irori は保存しません。
- **初めて接続するホストの鍵の確認**：表示された指紋（fingerprint）が正しいことを確かめて **続ける** を押します。`ssh` がそのホストの鍵を記憶し、次からは尋ねません。
- 入力が違っていたときは、`ssh` が同じ質問をもう一度出し、ダイアログにもそう表示されます。
- **キャンセル** を押すと、その接続をやめます。そのあと irori が勝手に尋ね直すことはありません。**接続**（フォルダを選ぶダイアログでは **再試行**）を押したときに、あらためて尋ねます。
- 踏み台を経由する接続では、踏み台と接続先のそれぞれが尋ねます。
- 質問の文面は `ssh` と接続先のホストが出したものです。心当たりのない質問には答えないでください。

最初の接続でも、尋ねられるのは 1 回のログインのぶんだけです。irori のファイルをホストに置く作業も、同じログインの中で行います。毎回の入力を省きたいときは、鍵を ssh-agent に登録するか、macOS・Linux なら ssh の `ControlMaster` で接続を共有してください。

接続が切れたあとに irori が自分で行う再接続（任せた仕事の報告を受け取るため）では、何も尋ねません。入力が必要なホストは、**接続** を押すまで未接続のままです。

## vault を追加する

ホストの行の **vault を追加** を押すと、ホストのフォルダをたどるダイアログが開きます。起動画面の **SSH ホストから**、または vault を追加するダイアログの **SSH ホスト** からも始められます。そこでは ssh の設定にあるホストを直接選べます。選ぶと、irori がそのホストを追加して接続し、フォルダを表示するところまで一度に進みます。

フォルダを選ぶか **ホストのフォルダのパス** に `/` で始まるパスを入力し、**vault にする** を押します。まだ vault でないフォルダには、ほかのフォルダと同じように `.irori/scope.json` を作り、`.gitignore` に `/contents/` の行を加えます。このコンピューターや別のホストですでに登録した vault は、二重には登録できません。

追加した vault は、表示中のワークスペースに入ります。

[irori mode](irori-mode.md) で irori agent に頼むこともできます（「gpu-box の `~/projects` の下のフォルダを vault にして」「gpu-box に Lab という新しい vault を作って」など）。irori agent は `irori hosts` でホストとそのフォルダを確かめ、`irori add --host` でフォルダを登録し、`irori create --host` で新しい vault（最初の commit を持つ Git リポジトリ）を作り、`irori clone --host` で GitHub のリポジトリをホストに取得します。このコンピューターでの操作と同じく、どれもあなたの許可を待ちます。作った vault は、頼んだワークスペースに入ります。

## 表示されるもの

ファイル、ノート、検索、バックリンク、コメント、プロパティ、オントロジー、Git の状態・履歴・差分は、ホストから読んで表示します。ノートは読み取り専用で開きます。

vault のパネルにはホストの名前が出ます。ホストにつながらないときは **接続** を押してつなぎ直します。vault のメニューの **一覧から外す** は、このコンピューターの一覧から外すだけで、ホストのフォルダはそのまま残ります。

## エージェントと話す

SSH ホストの vault でも、vault agent の列はこのコンピューターの vault と同じように使えます。会話の上に、どのホストで動くかが表示されます。エージェントは**ホストで**、vault の中で、ホストにインストールしてログインした CLI で動きます。

- 会話はホストに保存されます。履歴に並び、名前の変更・ピン留め・アーカイブ・削除・指示の編集・会話のコピーもそこで行います。
- 実行中の許可の確認や質問には、ここで答えます。
- 添付したファイルは、指示と一緒にホストへ送ります。
- 接続が切れても実行は続きます。実行中は irori が自分でつなぎ直し、切れていた間の表示を取り戻します。
- 返答に出てくるパスはホスト上のものなので、開けるリンクにはせず文字のまま表示します。

## irori mode から任せる

[irori mode](irori-mode.md) では、irori agent からこの vault に仕事を任せることもできます。irori agent が仕事を任せると、その vault のエージェントは**ホストで**、vault の中で動きます。途中の手順や許可の確認は irori agent の会話に出て、ここで答えます。irori agent を止めると、ホストの実行も止まります。

irori agent は必要なときに `irori ls`・`irori read`・`irori search` でその vault を読み、`irori send` でファイルを vault の作業フォルダに渡します。任せる仕事の本文は30,000文字までで、それより長い資料はこの方法で渡します。

作業中に接続が切れても、ホストでの実行は続きます。報告はホストで1日待ち、接続が戻ったときに irori が受け取ります。実行も報告の待ちもなく、irori もつながっていない状態が15分続くと、irori がホストで起動したものは自動で終わります。

## ターミナル

この vault のターミナル（``Ctrl+` ``、または表示していれば **ターミナル**）は、ホストに `ssh -t` でつなぎ、vault のフォルダであなたのログインシェルを開きます。接続とは別のログインなので、`ssh` がパスワードや検証コードを求めたら、ターミナルに入力してください。

## 知っておくこと

- あなたや irori agent がホストに送った文章（指示、任せた仕事、添付ファイル、`irori send` のファイル）は、ホストに残り、そのホストの管理者が読めます。ホストでの会話や CLI の記録も同じです。
- いまは対応していないもの：SSH ホストの vault をウィンドウから編集すること、その vault のエージェントの `irori` コマンド、接続フォルダ、ルーチン。
- 別のコンピューターで環境を復元すると、そのコンピューターに SSH ホストを追加するまで、この vault は使えない状態で表示されます。
