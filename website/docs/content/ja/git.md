## 変更を記録する

vault の **変更** でファイルを選び、差分を確認します。記録する変更をステージし、メッセージを入力して **コミット** を押します。

コミットは手元の履歴に残す操作です。まだリモートへは送られません。別のツールで部分的にステージした内容も保たれます。

## リモートと同期する

**その他の Git 操作** メニューの **Fetch** は、リモートの情報を取得します。**Pull** は作業ツリーがきれいで、履歴を早送りできる場合に取り込みます。

**Push** では vault・ブランチ・リモート・送るコミットを確認して送ります。Git の認証は既存の設定を使います。複数の vault の履歴はそれぞれ独立しています。

## 履歴と競合を確認する

**履歴** から以前のコミットと差分を開けます。履歴を統合する場合は **その他の Git 操作 → 履歴を統合** を選びます。

競合があれば共通の元・手元・相手の内容を確認し、結果を編集します。解決したファイルをステージし、内容を確認して統合のコミットを作ります。失敗した Push や Pull で、手元の変更が強制的に置き換わることはありません。

## GitHub に公開する

新しい vault の作成時に **GitHub にも作成** を選べます。既存のローカル vault では **Git を始める**、リモートがなければ **GitHub に公開…** から公開できます。

この操作には GitHub CLI `gh` とそのログインが必要です。公開画面でアカウント・リポジトリ名・公開範囲を確認します。既定は非公開です。irori はアプリ内でプルリクエストを作る機能は持っていません。

## submodule

vault には、ほかの GitHub リポジトリを submodule として入れられます。**変更** の **その他の Git 操作 → submodule を追加…** で、**GitHub のリポジトリ URL** と Knowledge の中の新しい **フォルダ** を入力し、**追加** を押します。Git が submodule をステージするので、vault でコミットして記録します。

submodule がある vault では、**変更** の **リポジトリ** で vault か submodule を選びます。それぞれが別々にコミット・Push・Pull し、履歴を持ちます。vault は、各 submodule がどのコミットにあるかを記録します。

vault を Pull すると、コミットしていない変更のない submodule も記録どおりに進みます。進められない submodule はその場に残り、結果にそう表示されます。起動画面の **GitHub から取得** で vault をクローンすると、submodule も取得します。まだ取得していない submodule は **未取得** と表示され、**取得** で取得できます。

## Contents の GitHub リポジトリ

プロジェクトのコードなど、GitHub のリポジトリを vault の Contents に置けます。vault の **接続** で接続元を **GitHub** にし、HTTPS か SSH のリポジトリ URL と、必要なら **ブランチ** を入力します。**保存先を選ぶ** で irori にクローンさせる場所を選ぶか、**手元のクローンを選ぶ** でこのコンピューターにあるクローンを選びます。名前を確認して **取得して接続**（手元のクローンでは **登録して接続**）を押します。

vault に記録されるのはリポジトリの URL だけで、`.irori/repositories.json` に入ります。クローンはコンピューターごとに持ちます。別のコンピューターでは、その接続の **取得** で、選んだ場所にクローンします。

リポジトリの接続は、**編集を許可** しない限り読み取り専用です。**最新にする** はリモートを取得し、いまのブランチを先へ進めます。コミットしていない変更や、そのクローンだけのコミットがあるときは何も変えず、理由を表示します。irori はそこでコミットや Push をしません。ターミナルかエージェントで行います。フォルダの接続と共通の操作は[同期フォルダ](sync-folders.md)を参照してください。

**GitHub リポジトリとブランチ**（エクスプローラーの Knowledge の見出しと、vault のホームの Knowledge のカードにあるブランチのボタン）は、vault のリポジトリ、その submodule、Contents に接続したリポジトリを、それぞれのブランチとともに一覧にします。**GitHub で開く** で、そのブランチのページを開けます。

## プログラムを実行するリポジトリ

リポジトリ自身の Git の設定がプログラムを実行する場合（フック、フィルター、diff や merge のドライバー、認証や SSH のヘルパー）、irori はその場所で Git を使う前に、実行されるものを示して確認します。**許可** すると Git を使います。内容が変わったときはまた確認します。**許可しない** を選ぶと、そのリポジトリでは Git を実行しません。心当たりのないものは許可しないでください。
