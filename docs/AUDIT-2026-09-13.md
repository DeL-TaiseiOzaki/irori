# Implementation audit — 2026-09-13

Scope: the current note/editor, native harness, workspace onboarding and read-only cloud connection preview. This audit does not mark the complete product requirements as delivered. These changes are included in the local 2026-09-13 pause checkpoint; see [CHECKPOINT](CHECKPOINT.md).

## Implemented missing lifecycle operations

- Workspace cards now edit names and scope selections or remove the saved profile. Editing retains temporarily offline scope IDs unless deselected. Removal does not unregister scopes, remove notes or change cloud declarations. Profile mutations are serialized.
- Disconnected cloud attachments now support changing their local name and removing their registration. Folder/mount IDs and account bindings survive a rename; collisions and unsafe names are rejected. Removal keeps provider files and user-created local bytes. Only an empty placeholder with the recorded device/inode is removed; live mounts block the operation.
- Authenticated accounts can be removed when unused. The host checks all persisted device bindings, including offline scopes, before deleting only the irori-owned rclone remote. Account mutations share the cloud service's queue.

## Corrected errors

- Connection polling schedules the next request after the previous one completes. Drive and folder loading states are independent, and stale responses cannot replace a newer selection.
- Failure to read one scope's connection declarations no longer stops reconnecting other scopes. Connection changes and new agent starts are disabled while workspace reconnection is underway.
- A removed mount placeholder can be recreated using a new recorded identity. Disconnect checks for a filesystem that remains mounted before reporting success; failed connections expose a disconnect action as well as retry.
- The 101st attachment is rejected before writing a declaration that the 100-entry reader would subsequently reject.
- Cmd/Ctrl+S on a read-only document does not attempt a host write.

## Verification

- `npm run build`: TypeScript and production frontend/host compilation pass. Existing dependency annotation and large-editor-bundle warnings remain; no compilation error.
- `npm test` with the local native rclone/OpenCode/Pi control probes enabled: **34 passed, 0 failed, 0 skipped**. These probes do not perform model inference or connect a Google account. Without their opt-in environment variables, four native probes are skipped.
- `npm run test:ui` under Xvfb: all three scripts pass, covering the actual Electron editor, session controls and both harness protocol fixtures. The cloud protocol fixture additionally exercises profile edit/removal, attachment rename/removal, account reference checks and removal, and independent reconnection with a deliberately malformed declaration in another scope. Existing ambiguous test locators were updated to address the intended card/dialog after adding management buttons.
- Mutation tests use disposable KBs. Existing bytes, other connections, provider identity, restart persistence, offline account references and placeholder cleanup are checked. Raw screenshots/logs remain in ignored `test-results`; no credentials or actual provider transcripts are tracked.

## Remaining gaps

The full matrix remains in [ACCEPTANCE](ACCEPTANCE.md). The main next work is:

1. Real Google consent, multiple real accounts and successful native mounts, then mounted-file access from every harness. This VM has neither deployment Google OAuth settings nor `/dev/fuse`; fixture checks do not satisfy those gates.
2. Git clone/fetch/diff/commit/push and conflict handling; cloud uploads with durable pending-write recovery; moved-folder/account-expiry recovery.
3. Native model-turn and restart/resume acceptance for OpenCode/Pi, remaining Codex question/denial gates, and native transcript redisplay/capability parity.
4. Offline space relocation/unregistration, note search/rename/backlinks, ontology editing, optional terminal, and versioned artifact provenance.
5. Windows/macOS packaging, signing, native Japanese IME and performance budgets.

The VM viewer was restarted using the normal irori window close action, which flushes drafts and shuts down native services. The updated preview is again served on loopback port 6080; the password is regenerated and stored in `.local/vm-preview/password`. Future host API changes also require an Electron restart; refreshing only the browser reconnects to the same desktop process.
