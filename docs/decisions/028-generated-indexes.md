# 028 — irori generates a bundle's folder indexes, and a hibachi's declaration travels

Date: 2026-10-07. Status: owner decision; implemented for 0.1.86.
Amends [ADR 008](008-graph-index-module.md) (the button and what it writes),
[ADR 015](015-page-properties.md) D1 (the root `README.md` is not a property page)
and the pull guard on `.irori/scope.json` ([GIT](../GIT.md)).

## Context

On 2026-10-07 the owner approved a simpler layout for irori-templete:
`Knowledge_Base/` holds `journal/`, `wiki/` and `ontology/`, and anything that
can be derived from the pages is generated by irori deterministically and
committed by the person. The graph index already worked that way (ADR 008). The
folder indexes did not: OKF 0.2 §8 gives every folder an `index.md` listing its
entries with their descriptions, and the template asked agents to keep them in
step by hand, so they drifted and differed between agents.

Using the template's knowledge bases in irori showed two more gaps:

- The repository's front page, `README.md`, counted as a knowledge page, so it
  opened with a properties block that said "type missing".
- A pull refused every incoming change to `.irori/scope.json`. A knowledge or
  contents folder renamed on one device (ADR 024), or new layer names or a new
  look, could never reach the others.

The owner kept the declared CSV pairs of `.irori/ontology.json` (ADR 008 D4),
and irori still assumes no folder names inside a layer (ADR 015's frame).

## Decisions

### D1 — The hibachi's root `README.md` is Schema

`classify` puts the `README.md` at the top of a hibachi in Schema, beside
`AGENTS.md`; any case of the name counts, as GitHub's front page does. A
`README.md` in a folder stays knowledge. So the root front page has no
properties block, is not searched, listed with the pages or indexed, and shows
in the Schema section (which is hidden while the hibachi agent is off, ADR 021).
`README.md` cannot be a layer folder name either.

### D2 — Folder indexes are generated with the graph index

When the knowledge folder (ADR 024) is an OKF bundle — its root `index.md`
opens with frontmatter naming `okf_version`, and `.property/property.json` reads —
**索引を更新** ("Update indexes") writes the folder indexes too. Otherwise none
are offered and nothing changes. A declaration in `.irori/ontology.json` still
stops the graph module from being generated, not the folder indexes.

- **Which folders.** The walk is the graph index's: the knowledge folder and its
  subfolders, without hidden folders, `node_modules`, aliases, blocked entries,
  the `ontology/` module, submodules (a folder holding `.git`) and nested
  hibachis. A folder gets an index when it holds a page (a `.md` other than
  `index.md`) in it or below it. Its `# Folders` lists the subfolders that get an
  index or already have an `index.md`, so a folder a person described before its
  first page keeps its line. An `index.md` in a folder with no page in or below
  it is left alone.
- **The text.** The root index keeps its frontmatter block byte for byte; no
  other index has frontmatter. `# Folders` comes first, `* [name](name/)` with
  ` - description` kept from the current index's line whose link is `name/` or
  `name/index.md`. Then one section per type in `property.json`'s `types`
  order, under the type's `heading` (`# <type>` when it has none):
  `* [title](file.md) - description`, in file-name order, the title falling
  back to the file name without `.md` and the description being the page's
  `description` on one line. Pages whose `type` is missing or undeclared come
  last under `# Other pages`. A heading appears only with entries; a line with
  no description ends at the link; sections are separated by one blank line.
  **Nothing else is kept:** an OKF index is a listing, and prose written into
  one is dropped on the next update. Names sort by code point in NFC.
- **Links.** Link text escapes `\`, `[` and `]`. A destination is the NFC name
  with whitespace, `%`, parentheses, angle brackets, `#`, `:`, `\`, backticks
  and control characters percent-encoded, so irori's own link reader resolves
  every line. irori now opens a link to a folder (`name/`) at that folder's
  `index.md`, where it used to refuse it.
- **Bytes.** NFC, `\n`, one final newline, UTF-8 without BOM, the same on any
  device. Files go through `FileService.writeGenerated`, hash-guarded, and only
  when their bytes change, after every output has been checked.
- **Freshness.** The panel's check reports how many indexes an update would add
  and rewrite, beside the graph's counts. The walk reuses the graph's remembered
  page facts (now with `description`) and keeps each `index.md`'s text by size
  and modification time.

The button is **索引を作成** ("Create indexes") while neither the graph module
nor any of those indexes exists. The text the module's own `ontology/index.md`
carries names the new button, so each module rewrites that file once.

### D3 — An incoming declaration that keeps the identity is taken

A pull or merge takes an incoming `.irori/scope.json` when it parses with the
same declaration schema, keeps the `scopeId`, and passes the checks a local
layer rename and registration apply: ADR 024 D5's folder names for every layer
folder it changes, layers that do not overlap, no layer inside another
registered hibachi and no registered hibachi inside its contents. This side must
not have changed the file since the merge base. A removed file, another
`scopeId` or a failed check is refused before the merge, with the existing
message. After the merge irori reads the declaration again, and the window
re-reads the hibachis, so layers, names and the look follow without a restart.
Connected folders under a renamed contents folder show as not connected, as
ADR 024 says; irori does not relink them.

## Consequences

- A knowledge base built from the template keeps its indexes current with one
  button, and its `lint` checks the same rule instead of writing indexes. The
  template states the rule (irori-templete `AGENTS.md`, **Indexes**); the two
  must change together.
- Prose in a folder index is lost on the next update. A folder's description is
  the one place a person writes into an index.
- The root `README.md` is no longer found by search or listed among backlinks,
  and opens without a properties block.
- A pulled rename moves the layer on every device; a device whose contents
  folder was renamed connects its folders again.
