# Initial measurements and verification evidence

Date: 2026-09-12. These are Linux development measurements, not Windows/Mac release benchmarks.

## Environment

Linux x86_64 container, AMD EPYC 7713 host reporting 128 logical CPUs and about 2 TB host-visible memory. Container resource limits and shared-host contention are not fully characterized. Node 24.21.0, Electron 44.3.0, Codex 0.154.0, Claude Code 2.1.232, Claude Agent SDK 0.3.269. Xvfb provides the display. No Google Drive mount or native platform was present.

Electron is a Vite production renderer plus bundled host, launched with Playwright instrumentation. The Linux root test passes `--no-sandbox`; that invalidates any inference about Chromium OS sandbox deployment. Codex separately encountered namespace restrictions and requested native approvals for fixture operations.

## Observations

- Initial UI readiness samples (process launch to visible welcome): 389–577 ms across development smoke runs. These are a handful of runs, not cold-start p95 or a supported-device commitment.
- A no-agent editing sample reported 706,164 KiB summed process-tree RSS (~689.6 MiB), including Browser, renderer, GPU, utility and Linux zygotes. Only five 500-ms samples were collected during that short test. It is not a stabilized idle benchmark.
- A both-agent UI workflow sample peaked at 1,049,792 KiB summed process-tree RSS (~1,025.2 MiB). At that sample, the tree included Claude Code (~347.9 MiB), Electron host/UI/GPU/utility and zygotes. 94 samples were collected at 500-ms intervals. Child CLI/adapter processes are included; there was no cloud workload to include.
- `app.getAppMetrics()` alone omitted zygotes from its reported list, so its app subtotal must not be mistaken for the whole process-tree total. Summed RSS double-counts shared memory; a native PSS/physical-footprint comparison is still needed.
- Installed Electron distribution: approximately 283 MiB on disk. Frontend build approximately 4.4 MiB. These are development file sizes, not signed installer sizes.
- Actual headless fixture turns: Codex 22,624 ms and Claude 15,849 ms in one passing run. These include provider/network/model and approval/tool latency and are not application typing/startup latency.
- Native startup cancellation probe: Codex 333 ms and Claude 632 ms from cancel request to released mutation lock. These probes cancelled around 1.5 seconds after launch; long-running tool-tree cancellation and pathological detached descendants remain unverified.

The Linux editing sample already exceeds the specification's proposed 400 MiB app-editing budget. No lightweight acceptance gate is marked passed. Measure Tauri + the same Node agent service/editor and native Electron on Windows/MacBook before finalizing the host or revising budgets.

## Repeatability and evidence handling

Use `npm run build`, `npm test`, `npm run test:ui`, `npm run test:agents`, `npm run test:lifecycle`, and the real-agent UI option in README. Real tests use fresh temporary KBs with Japanese/spaced paths and the existing native account. They must not mutate the two reference repositories or a user's existing KB.

`test-results/real-agents.json`, `ui-smoke.json`, `ui-smoke-real.json`, `lifecycle-agents.json` and `irori-desktop.png` are local evidence, ignored by Git. `scripts/process-metrics.ts` collects only pid/parent/RSS/process name, not command lines or credentials. Durable JSON evidence alongside this report strips fixture paths and process IDs.

Both native-account edits, permissions and the complete UI editor-refresh journey passed. Claude deny/user-input and both cancellations were observed. Codex's denial/question probe did not exercise the required request branches and must remain an explicit open gate.

The latest real-agent UI run also verified a dirty editor buffer during an actual Claude file edit. Both versions appeared in conflict review; the user-selected disk version was then reflected in the editor. [Captured application window](irori-initial-desktop.png).
