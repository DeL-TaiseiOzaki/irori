# Recovery audit and actionable backlog — 2026-09-22

The audit compared the workspace handoff with application `main` at `9c92f39`,
published preview 0.1.25, current source and disposable regression fixtures.
The owner then requested implementation of immediately actionable work and a
durable record of the overlooked issues. The changes below are prepared in

the pull request is merged and published. STATUS records integrated validation.

## Findings addressed in this change

| Finding and trigger | Result and regression evidence |
| --- | --- |
| Renaming a note loses the person's line marks and edit-time notices, because the author record is keyed by its old path. | Carry the existing marks through an application move and line-preserving link rewrites. Follow Git-detected renames when reading shared notes. Authorship and Git-note tests cover local moves, external renames and subsequent commit/export. |
| A new checkout does not receive `refs/notes/ai` until a separate Fetch. | Clone imports the notes too. No remote notes is normal; failed notes transport or integration preserves the checkout and displays a notice. Git-note tests use local bare remotes. |
| Moving or renaming an OKF page leaves `relations[].target` and page `sources[].resource` pointing to old paths. A two-node graph becomes empty on regeneration. | The move preview and guarded rewrite include these frontmatter references. Replace scalar spans without reserialising YAML, preserve comments/BOM/line endings, and leave unrelated fields intact. Move tests regenerate the graph and verify its edge survives. |
| Valid row counts can produce a CSV above the reader's 2 MiB limit; generation writes it before failing, leaving an unreadable module. | Check every generated file's byte size before writing any file. Tests use 1,000 short pages, 9,000 relations and long paths; existing module bytes remain unchanged on refusal. |
| A broken generated CSV hides the regeneration control, and a previously oversized file cannot be replaced through the normal reader. | Read guarded existing byte hashes independently of text decoding; expose regeneration after the host confirms there is no explicit declaration. Tests cover corrupt, binary and oversized generated files. Explicit declarations remain protected. |
| Portable NFC graph paths do not open decomposed Unicode filenames on a filesystem that distinguishes them. | Keep canonical CSV bytes and IDs; resolve module note paths to the checkout's actual spelling. Tests cover decomposed Japanese names/directories and alias rejection. |
| One failed mount-status request leaves a healthy Drive connection permanently in the error state, including after reconnect. | A successful check restores mounted state. A delayed check cannot revive an already disconnected mount. Connection tests exercise both transitions. |
| A disappeared mount makes every normal application-close attempt fail at unmount. | Continue only after both a valid RC list and filesystem observation confirm that the mount is absent. Still-listed, foreign, unverifiable and aliased mounts remain errors. No local bytes are deleted. |
| The concurrent-search regression test can hang because the second search reaches its gate before the first. | Wait until the first request is actually paused, release its gate in `finally`, and give the test a deadline. The superseding-request assertions are retained. |
| A normal save, including a longer rewritten reference, can exceed 2 MiB and fail only after overwriting the note. | Check UTF-8 byte size and NUL before touching the file or draft. Save and move tests prove oversized replacements preserve the original bytes and report the skipped update. |

The frontmatter omission was already listed in NOTE-LINKS, but its reason was
an undecided graph design. ADR 008 settled that design and introduced graph
generation; preserving those references was the missing integration work.
The other failures above were not covered by the passing baseline suites.
Integration review also caught a quadratic lookup in the first Unicode-path
repair: normalise each directory's names once into a lookup map, preserving
duplicate-name rejection without scanning every entry for every graph node.

## D04 work advanced without changing account permissions

New cloud-send preparations retain the exact owner, mount, folder, account and
shared-drive identities. The delivery engine rejects any mismatch before
observing or copying remote bytes, including after restart or account rebinding.
Old preparations without an account remain readable and their retained source
versions remain recoverable; they cannot silently acquire the current account
and be sent. Preparing a new record requires a ready, explicitly bound account.

Google remains read-only. No UI/IPC route invokes delivery, no OAuth scope was
changed, and no real account was contacted. Writable capability, re-consent,
binding the verified identity to the actual transport, remote completion and
real failure/restart acceptance remain D04 work. Local rclone tests demonstrate
the isolated delivery engine only.

Ordinary body links are intentionally not graph relations. Automatic graph
generation on save, cross-KB search, full transcript archives, wiki/HTML link
rewrites and the final external-writer race remain outside this change.

incomplete coverage, and unsupported outgoing metadata blocks a folder move.
Generation still writes files separately, not as a three-file transaction.
