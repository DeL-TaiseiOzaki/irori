# irori 0.2.64 preview 1 — full access asks nothing at the start

- A conversation in full access no longer stops at the start of a run for the
  dialog **エージェントの設定に、確認なしで動く部分があります** (Part of the agent
  configuration runs without asking). Hooks, MCP servers, plugins and project
  settings in the folder run as part of the full access you chose, and the
  conversation's log names what was used.
- What a run in full access used is remembered as allowed on this device. A
  conversation in standard access still asks about such configuration the first
  time it meets it and again after it changes.
- Questions from an agent, the confirmation of the irori agent's `irori add`,
  `connect`, `work`, `remove` and `run`, and the question whether to run
  without a Schema guard hook a CLI cannot run stay as they were
  ([ADR 009](../decisions/009-agent-access-and-extension-compatibility.md)).

## Verification

`npm run build`, `npm run format:check` and `npm test` pass on Linux. The new
`config-approval` test records configuration taken in full access without
asking and asks again after a change; the new `schema-reach` test runs the
OpenCode fixture in full access with a vault Schema hook, sees no dialog and the
log line naming the hooks, then sees standard access ask only once the hook
changes. The CLIs were exercised through their protocol fixtures only, not with
real accounts, and the change was not seen on Windows or macOS.
