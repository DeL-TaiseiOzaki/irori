# irori 0.1.101 preview 1 — Less work behind the same screens

irori does less work while you type and while agents run. Nothing on screen
changes: every view, label and interaction is as in 0.1.99.

- **Typing in a vault's composer** no longer redraws the whole window on each
  key. Only the composer's column follows the text.
- **irori mode while agents run** takes their streamed events once per frame,
  as the dock's columns already did, instead of redrawing the map and its
  cards for every event. This matters more with several threads at once.
- **Events from the host** cross into the window once and are shared by every
  part that listens (columns, irori mode, terminals, search, routines). Before,
  each of them received its own copy of every streamed event.
- **Long pages** are no longer split into frontmatter and body again on every
  keystroke, and their properties are parsed only when the frontmatter changes.
- **Startup with many vaults** resolves each vault's contents folders once,
  rather than once for every pair of vaults.

## Verification

`npm run build`, `npm run format:check`, `npm test` and every UI smoke of
`npm run test:ui`, each run alone under `xvfb-run`, pass.

- New unit tests cover the shared event subscription: one bridge subscription
  for any number of listeners, delivery in subscription order to the listeners
  present when an event arrives, and a throwing listener not keeping an event
  from the others.

Nothing was profiled; the gains are judged from what each change removes.
Not tried with real Claude Code or Codex, on Windows or on macOS.
