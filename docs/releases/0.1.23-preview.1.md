# irori 0.1.23 — Windows and Mac preview, a lighter package

The application package carried about 90 MB of packages that the running app
never opened. This preview stops shipping them and adds the licence notices the
bundled code requires. Nothing in the application itself changes. An installed
0.1.22 or earlier on either platform is offered this by **更新を確認**.

## What changed

**The package no longer carries what only the build needed.** irori's editor,
panels and their libraries are bundled into a few files when the application is
built, yet the package also carried every one of those libraries' own
directories — 271 packages of source that nothing loads. Packaging now keeps
only what the application's host process actually opens at run time, decided
from the built host itself, and drops the rest. On Linux the application
archive went from about 115 MB to about 22 MB; the parts that stay outside the
archive, the terminal helper and rclone, are unchanged.

**The bundled libraries' licences travel with the bundle.** Since their
directories no longer ship, the build writes one file,
`dist/third-party-notices.txt` inside the application archive, naming every
package whose modules went into the bundle, with its version, its declared
licence and the text of its licence files.

## Installing

**Windows 11 x64:** download `irori-0.1.23-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.23-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, the package check also asserts that every package the host
requires is present, that no other dependency is, and that the notices file is
present and names each bundled dependency at its installed version. Those
assertions were seen to fail against the previous package, against a build with
the removal disabled, and against a build whose notices withheld one package.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The Windows and Mac packages drop the same files; their exact sizes are in
their own CI job logs. rclone and Electron's own runtime are unchanged and remain
most of the download. Google connections remain read-only. Drive uploads, real
OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
