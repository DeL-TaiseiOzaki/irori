# irori 0.1.34 — Google Drive folders open on Windows

On Windows, a connected Google Drive folder showed as connected, but opening it
failed with `UNKNOWN: unknown error, realpath`, in the workspace's Google Drive
list and in a KB's materials alike. The folder was mounted correctly; the
failure was in how irori checked a path inside it. rclone mounts a Drive folder
on Windows through WinFsp as a volume attached to a folder, and Windows cannot
report such a volume's paths in the form Node's `realpath` asks for, so every
path inside the mount failed. irori now checks those paths one folder at a
time, as it already did for the folders above the mount, and still refuses a
link that would lead outside the connected folder.

The cloud connection dialog no longer shows the rclone version and a
"read-only" line when everything works. It shows a line only when something
needs attention, such as WinFsp not being installed.

## Installing

**Windows 11 x64:** download `irori-0.1.34-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.34-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally. Keep irori in **アプリケーション**:
the in-app update replaces the app where it is.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. A new test
makes `realpath` fail for every path inside a mounted folder, as it does on
Windows, and checks that the folder and a file inside it can still be listed
and opened while a link below the mount point is still refused. Against the
previous code it fails with the same `UNKNOWN` error.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Opening a real Drive folder
through WinFsp still needs a Windows 11 trial; the Mac's NFS mount is untested
on a device.

Read [the distribution notes](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/DISTRIBUTION.md)
