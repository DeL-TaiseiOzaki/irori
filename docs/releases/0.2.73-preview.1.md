# irori 0.2.73 preview 1 — Sign in to GitHub from irori

Until now, **設定 › アカウント** showed only an error naming `gh auth login`
when the GitHub CLI was signed out, and nothing in irori could sign it in
([ADR 062](../decisions/062-signing-in-to-github-from-irori.md)).

- **GitHub にログイン** runs `gh auth login --web` without a terminal. irori
  shows the one-time code gh prints; **コードをコピーして GitHub を開く** copies
  it and opens GitHub's device page. Once you approve there, the section shows
  the account by itself. **キャンセル** stops the waiting gh. The token is still
  kept by gh, never by irori.
- The same sign-in replaces the error in the restore sheet (**GitHub から環境を
  復元** on the start screen) and in the account picker of **GitHub に公開**.
  When gh is not installed, the section says so and links to its page.
- **Git の作成者** in the account section shows and changes the name and email
  Git records on commits (`git config --global user.name` and `user.email`).
  Signing in from irori fills in whichever is unset from the account: its name,
  and its public email or GitHub's private noreply address. A value already set
  is kept.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass on Linux.
`tests/github-sign-in.test.ts` runs the sign-in against a stand-in gh: the code
and page, the copy and open, the author filled only where unset, cancelling and
replacing a waiting sign-in, and gh refusing because of `GH_TOKEN`.
`scripts/account-ui-smoke.ts` now starts signed out and signs in from
**設定 › アカウント** before saving the environment. A real `gh auth login --web`
against github.com was not run.
