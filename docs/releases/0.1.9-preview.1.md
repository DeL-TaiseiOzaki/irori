# irori 0.1.9 — Windows and Mac preview, the reader chooses the Markdown typeface

This preview lets a reader pick the typeface a note is rendered in. An installed
0.1.8 or earlier on either platform is offered it by **更新を確認**.

## What changed

**Six typefaces for rendered Markdown.** The appearance menu in the sidebar now
holds two groups, テーマ and **Markdown フォント**, and the second offers システム,
ゴシック, 丸ゴシック, 明朝, 教科書体 and 等幅. Each item is drawn in the face it
selects, so the menu itself is the preview.

**Nothing is downloaded.** Every choice is a stack of fonts the operating system
already has, ending in a generic family, so it resolves offline and on a machine
that carries none of the named faces.

**Only the note changes face.** Editor controls, source views, the assistant
panel and the rest of the application keep their established type. The choice
applies without remounting the editor, so the note being written is not reloaded
and nothing is lost.

**The choice belongs to the device.** It is kept in `device-settings.json`
beside the theme and the pane sizes, not in a knowledge base, so it survives a
relaunch and does not follow a repository to another machine. A device that has
never chosen one gets ゴシック, the face notes were rendered in until now.

## Installing

**Windows 11 x64:** download `irori-0.1.9-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.9-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Which face a stack actually resolves to depends on what the device has
installed; 教科書体 in particular falls back to 明朝 where no textbook face is
present. The size, line height and weight of a note are not adjustable, and the
choice covers rendered Markdown only. Google connections remain read-only. Drive
uploads, real OpenCode and Pi model turns, Developer ID signing with
notarization, and cross-device history remain separate work.
