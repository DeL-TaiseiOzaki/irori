# irori 0.1.12 — Windows and Mac preview, which lines an agent wrote

A note you work on with an agent stops being legible the moment you cannot tell
your own sentences from the ones that arrived while you were reading something
else. This preview records who typed each line and shows it. An installed
0.1.11 or earlier on either platform is offered it by **更新を確認**.

## What changed

**The note says who wrote what.** When an agent working in a space writes to a
note in its knowledge layer, the lines it added are recorded against that run.
When you save, the lines you added are recorded as yours. Above the note, irori
states how many lines each CLI contributed; in source view, a mark at the left
edge of an agent's lines shows which ones.

**Lines nothing was observed about stay unmarked.** A note that arrived through
`git pull`, or was edited in another editor, carries no marks rather than being
claimed for whoever opened it. An absent mark is not a statement about a line.

**A line keeps its author when it moves.** Authorship follows the line's own
text, not its position, so inserting a paragraph above it, reordering sections,
or reflowing the document in the rich editor leaves it attributed. Rewriting a
line makes it yours, which is the point.

**The agent is told too.** When you send an instruction with a note selected,
the request now states which lines that note's saved bytes carry from you and
which from an earlier run. It is stated as a record, not as an instruction: what
an agent may do with your lines is your knowledge base's contract to make, not a
sentence irori adds.

**Nothing is written into the knowledge base.** The record is kept on this
device beside the existing run and source observations. No note is rewritten, no
front matter is touched, and nothing new is committed. A second device observes
its own work; the record does not travel with the repository yet.

## Installing

**Windows 11 x64:** download `irori-0.1.12-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.12-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

Behaviour tests cover a line surviving insertion, movement and a rich-editor
reflow that rewrites its bullet marker; a rewritten line becoming the reader's;
an unobserved line staying unattested; the reader's own save not being counted
as the agent's when the watcher reports it back; and the summary handed to an
agent carrying line numbers and no note text. An Electron suite drives a harness
fixture that appends to an open note during a run, restarts the application, and
reads the attribution back.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The record is device-local: it does not reach a collaborator, a second machine,
or an agent running outside irori. Two lines with identical text share one
attribution, and lines of three characters or fewer once punctuation is removed
carry none. Any write that lands in a space while one of its runs is executing is
attributed to that run, so editing the same checkout in another editor during a
run will misattribute those lines. Only Markdown in the knowledge layer is
tracked. The rich editor states a total rather than marking each block; source
view marks the lines. Google connections remain read-only. Drive uploads, real
OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
