# irori 0.2.35 preview 1 — errors you can see, and changes that follow Git

- Moving the open note into another vault no longer shows an error for the
  place it left. The page follows the note, as it does within one vault.
- A vault's **Changes** count and its Home follow a commit, a checkout or a
  staging made outside irori, in a terminal or by an agent, without
  **Refresh**.
- **Set up the irori agent** says why it could not, beside the button, when
  the chosen folder already holds files.
- In irori mode, on the Routines page, on the irori agent's screen and while
  the page is out of sight, an error now shows over the window instead of
  being lost.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/watcher-host-load.test.ts` commits in a real repository and checks that
the vault watcher hears `.git` without watching its objects. The UI smokes
cover each case: `vault-split-ui-smoke` (now part of `npm run test:ui`) moves
the open note with its new place resolving slowly, `git-ui-smoke` commits
outside irori, and `your-ai-ui-smoke` sets up in a folder holding `.claude/`
and attaches a file over the limit in irori mode. Each of these failed before
the change.
