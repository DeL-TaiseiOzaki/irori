# irori 0.2.5 preview 1 — Files and folders, dropped in

The Knowledge and Contents lists work like Explorer or Finder
([ADR 036](../decisions/036-explorer-as-file-manager.md)). The menus, moves and
file making of 0.2.2 reached readers with 0.2.4; this preview adds drops.

- **Drop files or whole folders from Finder or Explorer** onto a folder in
  Knowledge or an editable connected folder in Contents to copy them in. A
  folder comes with everything inside it, except hidden entries such as
  `.DS_Store`. A name already there gets a `2`, for files and folders alike.
- **A closed folder opens** when a drag is held over it, so a drop can reach the
  folders inside. The status line counts the files as they are added.

Up to 100 MiB per file and 2,000 files per drop go through irori; more goes
through the file manager.

## Verification

`npm run build`, `npm run format:check`, `npm test` and every UI smoke of
`npm run test:ui`, each run alone under `xvfb-run`, pass.

- New unit tests read a dropped folder tree in batches, leave hidden entries
  behind, refuse a drop over the file limit, and give a brought-in folder a free
  name.
- `explorer-ui-smoke` now holds a drag over a closed folder in a connected
  folder until it opens and drops two files there, one keeping both.

Folder drops are read from the browser's entries; the UI smoke can only drop
files, so a real folder dragged from Finder or Explorer is untested. Not tried
on Windows or macOS.
