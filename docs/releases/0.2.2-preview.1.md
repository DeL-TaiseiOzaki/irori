# irori 0.2.2 preview 1 — Folders and files of any kind

The Knowledge and Contents lists now work like Explorer or Finder
([ADR 036](../decisions/036-explorer-as-file-manager.md)).

- **Right click, or a row's ⋯,** for **New note**, **New file**, **New folder**
  and **Add files…** in a folder, and **Rename**, **Move** and **Delete** for a
  file or folder. **Show in Finder** (Explorer, file manager) opens its place.
  F2 renames and Delete deletes the selected row.
- **Drag a row onto a folder** to move it. **Drop files from Finder or
  Explorer** to copy them in; a name already there gets a `2`.
- **Links follow in Knowledge.** Renaming or moving a folder, an image or a
  CSV rewrites the links to it, and the comments and records of the notes
  inside go with them, as a note's move already did.
- A note deleted from Knowledge still goes to **Deleted notes**; other files
  and folders go to the system trash.
- `irori move` lets agents move files and folders of Knowledge the same way.
- A new empty CSV shows as empty rather than as an error.

## Verification

`npm run build`, `npm run format:check`, `npm test` and every UI smoke of
`npm run test:ui`, each run alone under `xvfb-run`, pass.

- New unit tests cover creating, bringing in, moving and deleting in both
  layers, the refusals (taken names in any case, the knowledge folder, a folder
  holding a vault, read-only connections) and the links, comments, drafts and
  note places a folder move carries.
- A new UI smoke, `explorer-ui-smoke`, makes a folder and a CSV from the right
  click, renames a folder and checks its links, drags a file onto a folder,
  copies a dropped file in, deletes a note with the Delete key, and makes a
  folder and adds a file in a connected folder.

Not tried on Windows or macOS, and drops from a real file manager are checked
only with a synthetic drop.
