# irori 0.1.8 — Windows and Mac preview, today's note where the knowledge base says

This preview adds the daily note. An installed 0.1.7 or earlier on either
platform is offered it by **更新を確認**.

## What changed

**A knowledge base declares where notes go.** A KB may carry
`.irori/notes.json`, tracked with the repository, naming the folder the new-note
dialog offers and where today's note lives. The recommended template writes it
when a knowledge base is set up; a KB without it behaves as before.

**今日のノート.** With a daily path declared, a button in the knowledge base
toolbar and on the welcome screen opens today's note. The first time each day it
is created from the declared template, with `{{date}}`, `{{yyyy}}`, `{{MM}}`,
`{{dd}}` and `{{datetime}}` filled in; after that the existing note is opened
unchanged. Paths use the device's local date.

**The new-note dialog follows the declaration.** When no note of the KB is open,
the dialog offers the declared folder instead of `Knowledge_Base/Notes`.

Declared locations must stay in the knowledge layer, and a template must be a
real file of the KB outside `contents/`; anything else is reported.

## Installing

**Windows 11 x64:** download `irori-0.1.8-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.8-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The daily note's date format is fixed to the tokens above, and the declaration
is written by hand or by the KB's own skills, not from the UI. Google
connections remain read-only. Drive uploads, real OpenCode and Pi model turns,
Developer ID signing with notarization, and cross-device history remain separate
work.
