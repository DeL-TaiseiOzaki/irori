# irori 0.2.45 preview 1 — edits after a background agent finishes

- Claude Code could no longer edit or write files in the part of a reply that
  began when a background agent finished, or after a message to one of its
  agents. Each Edit or Write came back at once as "The user doesn't want to take
  this action right now", though nobody had refused it. The Claude Agent SDK
  closed Claude Code's input at the reply's first result, so the hook irori
  attaches to file edits could not be reached. irori now uses SDK 0.3.284,
  which keeps the input open for that later part
  ([claude-code #88203](https://github.com/anthropics/claude-code/issues/88203)).

## Verification

`npm run build` and `npm test` pass. With SDK 0.3.284, a real Claude Code CLI,
`bypassPermissions` and a PreToolUse hook on `Write|Edit|MultiEdit|NotebookEdit`,
a reply that launches a background agent and edits a file once it reports
reaches the hook and both the Edit and the Write succeed; with SDK 0.3.269 the
same reply had both cancelled without the hook being called.
