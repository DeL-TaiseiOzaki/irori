# irori 0.1.44 — Resolving a conflict after the file changed

**Fixed:** while you resolve a merge conflict in **変更** (Changes), a change to
the same file from outside irori makes **統合内容を保存して解決** refuse once and ask you
to look again. That is intended. The next attempt could be refused as well,
though, until irori noticed the change on its own, which on a slow disk could
take a while. irori now reads the conflicted file again as soon as it refuses,
so the next attempt uses what is on disk. Your merged text is kept either way.

## Installing

**Windows 11 x64:** download `irori-0.1.44-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.44-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

The Git UI test that changes the file during a resolution passed three times in
a row locally. On CI it had failed twice in the preceding runs, at exactly this
second attempt. The unit tests and the other UI suites are unchanged.
