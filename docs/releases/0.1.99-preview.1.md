# irori 0.1.99 preview 1 — Threads in irori mode

irori mode now runs several conversations with the irori agent side by side,
keeps them per workspace, and lets a stopped thread take the next instruction
([ADR 034](../decisions/034-irori-mode-threads.md)).

- **Threads in columns.** Beside the map and on the routines page, the irori
  agent shows in the same columns as a vault's agent, with tabs, history and a
  composer in each. **列を追加** adds a thread beside the others, up to four.
  Closing a tab or a column never stops its run; a thread still running comes
  back as a tab. The map's lines follow the hand-offs of every thread.
- **Each workspace keeps its own threads.** The threads and columns in irori
  mode are those of the workspace open, and come back as they were when you
  return to it. irori no longer shows an irori agent conversation from another
  workspace, including one opened from the routines page.
- **A stopped thread goes on.** After 停止, sending another instruction runs
  the one already waiting and then the new one, in a vault's column as in irori
  mode. A paused queue says 一時停止中.
- **Two threads at once in one folder.** Two irori agent threads starting
  together no longer fail on a folder the other has just made, and vaults that
  two runs add to a workspace at the same moment are both kept.

## Verification

`npm run build`, `npm run format:check`, `npm test` and `npm run test:ui` pass.

- A new UI smoke, `irori-threads-ui-smoke`, runs two irori agent threads at
  once on a Codex protocol fixture. It checks the four-column limit, a closed
  column's run kept as a tab, and a stopped thread taking a new send after its
  queued one, in irori mode and in a vault column. It also checks that two
  workspaces keep separate threads, columns and history, and that the host
  refuses another workspace's conversation.
- New unit tests run two Codex threads of the irori agent at once in one
  folder, each with its own native session. They also cover definitions
  written by runs at once, vaults added to one workspace by runs at once, and
  the workspace check on a named conversation. Without the fixes these fail.

Not tried with real Claude Code or Codex. The owner's report of one
conversation shown in every workspace was not reproduced with the protocol
fixtures, so it is fixed by making every irori mode view per workspace rather
than by one found cause.
