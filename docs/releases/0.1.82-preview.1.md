# irori 0.1.82 preview 1 — Small fixes where copies had drifted

Several checks and messages had been copied from one place to another and
drifted apart. They now share one definition.

- A file or folder whose name starts with two dots, such as `..notes`, counts
  as inside its folder again. The irori agent may write it, and the irori
  agent's folder no longer refuses it.
- An instruction to a hibachi agent is limited to 32,000 characters in the
  message box, the same limit irori checks when it is sent. Before, the box
  accepted up to 100,000 characters and the longer message was refused after
  sending.
- A GitHub answer larger than 64 KB, such as a large saved environment, is read
  whole instead of being cut and failing to parse. An answer over 4 MB is
  refused with its own message.
- Errors on the irori mode map, the model picker, page properties and the file
  viewer no longer read "Error: Error: …".
- Comment times follow irori's language setting instead of the system's.

Unused code was removed: a document toolbar component nothing showed, a
Schema list property nothing read, and an unused argument and import in the
agent service.

## Verification

A unit test reads a 146 KB GitHub answer with Japanese text through a stand-in
gh and fails on the previous code. The type check also runs with unused locals
and parameters reported for the changed files. Not tried with a real GitHub
account, Windows or macOS.
