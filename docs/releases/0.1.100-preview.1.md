# irori 0.1.100 preview 1 — Knowledge at the vault's root

A vault's knowledge folder can now be the vault's root, so `index.md`,
`journal/`, `wiki/` and `ontology/` sit at the top of the repository instead of
under `Knowledge_Base/` ([ADR 035](../decisions/035-knowledge-at-the-vault-root.md)).

- **Choose the root.** In the vault's settings, **層** has **vault のルート**
  beside the Knowledge folder; the irori agent uses
  `irori layer <vault> knowledge .`. The folder's pages move up beside
  `AGENTS.md`, `README.md` and `contents/`, and the emptied folder goes. Links,
  `sources`, comments, unsaved drafts, `.irori/notes.json` and this device's
  records follow. If a name is already at the root, nothing moves and irori
  names what is in the way.
- **And back.** Choosing a folder name again moves the knowledge back into it.
- **Indexes at the root.** **索引を更新** writes `ontology/` and the folder
  indexes at the root; `AGENTS.md`, `README.md` and `contents/` stay out of
  them.
- **Templates in this layout.** A folder added for the first time with an OKF
  `index.md` at its root and no `Knowledge_Base/` keeps its knowledge at the
  root without any setting.

## Verification

`npm run build`, `npm run format:check`, `npm test` and `npm run test:ui` pass.
New unit tests move a vault's knowledge to the root and back, with its links
(including a moved page's links to contents and Schema), rooted `sources`,
comments, drafts and note places, refuse a move that would land on a taken
name, generate the graph and folder indexes of a bundle at the root, recognise
such a bundle when it is added, and run `irori layer <vault> knowledge .`.
