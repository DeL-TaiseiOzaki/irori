# irori 0.2.79 preview 1 — Find in a PDF reaches its page, and a vault host keeps its place

- **Find in a PDF** shows an occurrence on a page not drawn yet. A PDF draws a page
  only once it is in view, and the find bar could count the occurrence without
  bringing its page there: when the word was typed while the PDF still loaded, or
  when the search the opened document makes overtook the one typed. The count
  read **1 / 1** while nothing was marked. Now that search brings the occurrence
  into view and marks it.
- **A vault on an SSH host** no longer fails to connect with "the vault host did
  not start" when you connect just as its idle vault host ends. The ending host
  removed the files of the one starting in its place, which left that one
  unreachable and could leave two vault hosts in the folder.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass on Linux under Xvfb.

- The find smoke now types the word while the PDF loads. Without the change it
  fails every time, as CI had on two runs; with it, it passes.
- `tests/find-in-file.test.ts` covers the search that is overtaken.
- `tests/vault-host-place.test.ts` covers a host ending while another takes its
  place. The vault host built with a deliberately slow shutdown was run against
  both versions: before the change the new host's files were removed and a third
  host started, and after it one host stays.
- Four tests that read a result before it was written now wait for it: the
  settings smoke, the pasted file in the explorer smoke, the shared Schema smoke
  opening settings while the start screen still showed, and the Git process limit
  test.

Not tried on macOS or Windows.
