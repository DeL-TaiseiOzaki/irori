# irori 0.2.68 preview 1 — a vault can live on an SSH host

A vault no longer has to be on this computer. One on a Linux machine you reach
with `ssh` shows in a workspace beside your other vaults, and the irori agent
hands its agent work that runs there
([ADR 061](../decisions/061-vaults-on-ssh-hosts.md)).

- **設定 › SSH ホスト** adds a host by a name and what you would type after
  `ssh`: a Host of your ssh configuration, or `user@host`. irori uses this
  computer's own `ssh`, with your keys, agent and configuration. It cannot
  answer a password, a passphrase or a host-key question, so `ssh <destination>`
  must connect by itself first.
- The first connection puts irori's own files under `~/.irori-host` on the
  host: the Node it runs on (the official build, about 55 MB, downloaded here
  and sent through the connection) and its vault host. The host needs no
  internet access and nothing is installed system-wide.
- **vault を追加** on a host chooses a folder there. Like a folder on this
  computer, it gets `.irori/scope.json` and a `/contents/` line in `.gitignore`
  when it is not a vault yet. A vault already registered here or on another
  host is refused: one vault, one place.
- For now such a vault is **shown, not changed**: its files, notes, search,
  backlinks, comments, properties and Git status, history and diffs are read
  through the host, and a note opens read-only.
- In irori mode the irori agent is told which vaults are on which host. With
  `irori call` the vault's agent runs **on the host**, in the vault: what it
  runs, runs there. Its steps and its permission requests show in the irori
  agent's conversation, and you answer them here.
- The irori agent reads such a vault when it needs to, with `irori ls`,
  `irori read` and `irori search`, and gives it a file with `irori send`, which
  puts it in the vault's work folder. A handed task holds 30,000 characters;
  longer material goes this way.
- If the connection is cut while an agent works on the host, the run goes on,
  and irori collects its report when the connection is back. With nothing
  running and no irori attached for fifteen minutes, what irori started on the
  host ends by itself.

What to know:

- The CLI the irori agent runs on (Claude Code, Codex…) must be installed and
  signed in **on the host** for a hand-off there.
- Text the irori agent sends to a host, in a task or with `irori send`, stays
  on that machine and is readable by whoever administers it.
- Hosts are Linux on x64 or arm64 with glibc 2.28 or later.
- Not yet for a vault on a host: editing in the window, talking to its own
  agent directly, the terminal, connected folders and routines.

## Verification

`npm run build`, `npm run format:check` and `npm test` pass on Linux.
`tests/remote-hosts.test.ts` stands this machine in for a host and covers the
installation, a vault's reads, the refusal of a vault registered twice, a
hand-off that works on the host, the reads and the file sent on demand, a
permission request and a configuration approval answered on this device, a
hand-off stopped with the irori agent, and one that goes on while the
connection is cut. The same was run over a real `ssh` to another account of a
Linux machine, with Node downloaded from nodejs.org (`IRORI_TEST_SSH`).
`scripts/remote-hosts-ui-smoke.ts` adds a host and a vault in a real Electron
under Xvfb, with a stand-in `ssh`.

Not tried: a Windows or macOS client, a real network between the two machines,
and a real CLI with an account on the host. The tests use the stand-in CLIs.
