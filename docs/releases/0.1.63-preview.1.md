# irori 0.1.63 — conversations run side by side

- A hibachi's conversations now run at the same time, as Claudian's tabs do.
  Start a conversation, open **新しい会話**, and send there while the first one
  is still working. Each conversation has its own CLI process and session.
- The hibachi agent's panel shows the open conversations as tabs once there are
  two, marking the ones that are working or waiting for an answer. Opening a
  conversation from **履歴** or choosing another CLI adds a tab. A running
  conversation's tab stays open until its run ends.
- A send to a conversation that is running is queued in that conversation and
  waits for its run alone. **停止** stops only the conversation on show.
- The person's own conversations in a hibachi handed to the irori agent run
  beside the irori agent's work instead of waiting for it.
- Runs in one hibachi are not coordinated: two conversations editing the same
  file can overwrite each other, as in Claudian. Git operations and hibachi
  settings still wait until every run in the hibachi has ended.

See [ADR 020](../decisions/020-parallel-conversations.md).

## Verification

New tests cover two conversations of one hibachi running at once with the
Pi protocol fixture, each queue waiting only for its own conversation, stopping
one conversation while the other goes on, and a second run in a running
conversation being refused. The Electron UI suite sends in a second tab while
the first conversation's run works, checks the tab marks and closing, and
switches between tabs.

Real Claude Code, Codex and other CLI turns running side by side, and installed
Windows and macOS builds, were not tested. No preview is published until this
branch is merged and the native release jobs succeed.
