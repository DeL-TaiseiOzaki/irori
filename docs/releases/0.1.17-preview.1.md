# irori 0.1.17 — Windows and Mac preview, links that follow a moved note

A knowledge base is pages pointing at each other by relative path. Until this
preview, renaming or moving a note left every link to it pointing at nothing,
and a note with its own relative links could not change folder at all. An
installed 0.1.16 or earlier on either platform is offered this by **更新を確認**.

## What changed

**名前・場所 keeps links correct.** Before the note moves, the dialog says how
many links in how many other notes will be updated. **リンクも更新する**, on by
default, rewrites them after the move, together with the moved note's own links
so they still lead where they did from its new folder. The status line then
says how many were updated.

**Only the link target changes.** The link's text, its title and `#見出し`, the
way it was written — `<…>` or percent-encoded — line endings and front matter
stay as they were. Moving the note back puts the links back by the same means.

**Nothing is overwritten.** A note that changed while the move ran, or that
holds unsaved text, is left as it is and named in the status line, and the move
still stands. With **リンクも更新する** off, the note moves byte for byte and
nothing else is touched, as before.

## Installing

**Windows 11 x64:** download `irori-0.1.17-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.17-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

For this change, behaviour tests cover every way a link target is written, code
that only looks like a link, preserved line endings and front matter, the moved
note's links to its neighbours and to itself, several linking notes in nested
folders, a note edited during the move, and declining the update. An Electron
suite renames a page and moves another into a folder, reads the dialog's count
and the status line, and follows the rewritten links.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Wiki links `[[…]]` and HTML `src=`/`href=` are not rewritten, so a note holding
one still refuses a folder change. A link whose case differs from the file's
name, a link from another registered knowledge base and front-matter
`relations` are not rewritten. The count shown before a move covers the other
notes; the note's own links are described rather than counted. Source view does
not follow links, a heading after `#` is not scrolled to, and a missing page is
not offered for creation. Google connections remain read-only. Drive uploads,
real OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
