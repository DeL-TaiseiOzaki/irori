# irori 0.1.37 — Google Drive folders live in a KB's materials

The separate **Google Drive** frame at the bottom of the sidebar is gone. A
Drive folder is now always connected to a KB's materials and appears under
**個人の資料** or **チームの資料** with that KB. Connect one with **接続** beside
the KB in the materials pane, or with **クラウド接続** at the top, which now opens
the connections of the KB you have open. Agents working in the KB can use its
Drive folders, and the KB records which folders it uses, without any sign-in
details, so others can connect the same folders with their own accounts.

- **Folders you connected to the workspace before.** They are no longer
  connected by themselves. Open **クラウド接続** in the KB you want them in and
  press **この KB に移す** under "ワークスペースに接続されている Drive フォルダ".
  The folder keeps its name and its editing setting, and changes that were still
  waiting to upload are sent once it is connected there. If the KB already
  connects the same folder, the workspace's duplicate is simply removed.
- **Removing a workspace** that still has such folders now works; only irori's
  records of them are removed, never files.
- **"Drive への送信準備"** in 資料と成果物 offers the open KB's Drive folders.

A workspace with no KB can no longer use Drive folders.

## Installing

**Windows 11 x64:** download `irori-0.1.37-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.37-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally. Keep irori in **アプリケーション**:
the in-app update replaces the app where it is.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. The
workspace Drive UI test now seeds workspace connections as earlier versions
wrote them, checks that no separate Drive frame appears, moves them into a KB
with their IDs, prepares an upload to the KB's folder, restarts, and removes a
workspace that still held a connection. Service tests cover moving (a duplicate
folder, a name already used, keeping the mount ID) and removing a workspace.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Knowledge records that
point at a file in a workspace connection keep their old location.

Read [the distribution notes](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/DISTRIBUTION.md)
and [the full release plan](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/RELEASE-PLAN.md).
Report the displayed version, OS and exact error through
[GitHub Issues](https://github.com/DeL-TaiseiOzaki/irori/issues), omitting private
notes, credentials and OAuth URLs. Source is MIT licensed; dependencies retain
