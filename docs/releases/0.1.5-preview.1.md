# irori 0.1.5 — Recovery and note tools Windows preview

This unsigned Windows x64 testing update keeps unsent writing across restarts,
adds safe note organization and recovery, an explicit update check, and opens
search results at the matching text. Close the earlier app and install
`irori-0.1.5-windows-x64-Setup.exe`. The startup screen and workspace display
**0.1.5 Preview**, so the running version can be checked directly. Existing KB
folders and account configuration keep their locations; this update does not
require creating a new workspace or registering the Google client again.

## Changes to try

- Type into the assistant composer or a commit message, close the app, and
  reopen it. The unsent text returns to its input field. An unfinished text
  conflict resolution is offered as a recovery preview and restored only with
  **下書きを編集に戻す**. Nothing is sent or resolved automatically, and drafts
  stay in private device storage, never in KB Git metadata.
- Create a note with a KB-relative destination folder, then use **名前・場所** to
  rename or move it inside the same Knowledge_Base scope. Note bytes are
  preserved and irori-created `_assets/image-HASH.ext` images are verified and
  copied before the source is removed. Moves that would break other relative
  links are blocked rather than guessed; incoming links are not rewritten.
- Delete a note and restore it with **削除したノートを復元**. The exact text is kept
  in device-local recovery storage first, and a restore never overwrites an
  occupied path.
- Press **更新を確認** on the startup screen or in the workspace. Only a click
  queries the official release endpoint, with bounded bytes and a request
  deadline; opening the release page or installer link needs a second explicit
  action. There is no background check, download or automatic installation.
- Open a KB search result: the first query match on that line is selected and
  scrolled into view. Markdown stays a document, so a match is selected only
  when source and visible text map unambiguously; otherwise a limitation notice
  is shown instead of a guess.
- A failed image now shows its stored URL beside a recovery instruction without
  removing or rewriting the Markdown link.

CI's Windows package job launches the copied application outside its checkout
and verifies SDK imports, save/undo/redo and editing after autosave, native OS
clipboard image paste and reopening, the CSV graph, Japanese note and terminal
file saves, private composer and conflict drafts, recoverable deleted notes
after restart, single-instance ownership and bundled rclone. Configured OAuth
checks stop at the local browser handoff. Tests use disposable data and do not
execute a real model turn.

## Remaining boundaries

The installer is unsigned, so Windows may display its unknown-publisher warning.
Passing CI is not acceptance on an installed Windows 11 device: installation,
upgrade from 0.1.4, IME and real CLI accounts still need the owner's device
trial. Please report the displayed version and the exact steps.

Google connections remain read-only and Windows mounting still needs WinFsp.
Real Google consent and native mounts, Drive uploads, real OpenCode/Pi model
turns, installer signing, a Mac release and cross-device history remain separate
work. A hard crash can still lose an in-flight draft; drafts are not an
exactly-once or power-loss guarantee. Mac downloads remain unavailable.

Read [the recovery and note tools details](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/RECOVERY-AND-NOTE-TOOLS.md)
and [the full release plan](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/RELEASE-PLAN.md).
Report the displayed version, OS and exact error through
[GitHub Issues](https://github.com/DeL-TaiseiOzaki/irori/issues), omitting private
notes, credentials and OAuth URLs. Source is MIT licensed; dependencies retain
their upstream terms.
