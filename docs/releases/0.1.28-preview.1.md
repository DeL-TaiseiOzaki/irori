# irori 0.1.28 — Show or hide code assistance with one button

The document toolbar now has **コード支援 ON / OFF**. An installed 0.1.26 or
earlier on either platform is offered this by **更新を確認**. 0.1.27 was not
published on its own, so an update from 0.1.26 also brings what it added,
summarised below.

## What changed

**One button for code assistance.** **コード支援 ON / OFF** switches syntax
coloring, line numbers, folding, bracket assistance and available completions
together, both in source files and in Markdown code blocks. The choice is saved
on this device and restored after restarting irori. If saving the choice fails,
irori reports it and keeps the previous display.

**Source files are colored by language.** A source file picks its language from
the filename. An unknown filename stays plain text.

Switching keeps the same editor, text, selection and Undo history, and does not
save the note. Plain editing, search, person-line marks and native agent
execution stay available with assistance hidden. The button is not shown in CSV
table mode, which has no code editor.

## Also in this preview, from 0.1.27

**Choose how much access an agent has.** The conversation controls offer native
access behavior or full access for Codex, Claude Code and OpenCode. Each option
describes what that CLI actually does. Pi keeps its own settings. Queued
messages keep the mode they were sent with. Changing the mode starts a new
native conversation while irori keeps the displayed history, so an elevated
session is never reused under a different label.

**Recover retained cloud-send preparations.** The startup screen and the
workspace sidebar list retained send preparations on this device, even after
their connection or workspace has been removed. An exact retained version can be
restored into a new local file without overwriting existing files.

Google connections still request read-only access. Full agent access does not
grant Google write permission or send retained preparations.

Details: [0.1.27 notes](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/releases/0.1.27-preview.1.md),
[code assistance](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/EDITOR-ASSISTANCE.md).

## Installing

**Windows 11 x64:** download `irori-0.1.28-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.28-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behavior tests and all fifteen Electron UI suites pass on the
merged code. The new suite switches assistance repeatedly on a clean and an
unsaved source file and on a Markdown code block, and checks the selection,
Undo/Redo, that no note is saved, persistence across restart and recovery from a
failed settings write.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac. Language diagnostics and project run buttons are
not part of code assistance yet. Writing to Google Drive and running VS Code
extensions remain separate work.
