# irori 0.2.96 preview 1 — A new vault chooses its layers

- The forms that make a vault — opening a folder, cloning from GitHub, creating
  a new one, and choosing a folder on an SSH host — now show
  **この vault が持つ層**, with Knowledge and Contents both on at first
  ([ADR 072](../decisions/072-a-new-vault-chooses-its-layers.md)). Turning
  Knowledge off registers a repository of code as a workspace vault in one
  step, its files in Contents. A folder that is already a vault keeps the
  layers it declares.
- Those forms no longer ask for a category (分類), and a new vault carries none
  instead of 個人. The vault's settings still give a vault a category of any
  name; existing vaults keep theirs.
- Agents: `irori clone`, `irori create` and `irori add` take `--layers`, and
  write a category only with `--category`. `irori list` and `irori set` name a
  category only when the vault has one.

## Verification

`npm run build` and `npm run format:check` pass. `npm test` passes except
`tests/ssh-config.test.ts` "what is shown of each host is what ssh itself
resolves", which fails on the shared Linux host without this change too.
`tests/vault-layers.test.ts` covers registration with layers and without a
category; `tests/irori-command.test.ts` covers `--layers` on `create` and `add`
and a declared folder keeping its own. `scripts/ui-smoke.ts` checks the layer
choice in the registration form and that no category is asked, in pull request
CI on Linux under Xvfb. The SSH host's form was not exercised against a real
host. Not tried on macOS or Windows.
