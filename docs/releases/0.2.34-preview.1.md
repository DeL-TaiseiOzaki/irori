# irori 0.2.34 preview 1 — a handed vault runs as its own vault agent

- On every CLI, the irori agent hands a vault's work to that vault's agent with
  `irori call`. The vault agent runs inside its vault, with its own rules,
  hooks, skills and sub-agents, rather than as a sub-agent inside the irori
  agent's session. irori no longer writes `vault-*` definitions into the irori
  agent's folder.
- A hand-off runs in the irori agent's access mode. Its permission requests
  also show with the irori agent, labelled with the vault.
- A vault can define its own agent as `vault-agent` in `.claude/agents`,
  `.codex/agents` or `.opencode/agents`. The irori agent sees its description,
  and the vault agent follows it for handed tasks.
- A folder's sub-agents work on any CLI. Definitions in `.claude/agents/*.md`,
  `.codex/agents/*.toml` and `.opencode/agents/*.md` reach the vault agent
  whether it runs on Claude Code, Codex or OpenCode. A definition's model is
  used only on its own CLI.
- The irori agent's screen lists each vault's agent by name.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/your-ai.test.ts` covers hand-offs through `irori call` with a Claude
Code stand-in playing both sides: attribution, a forwarded request, full
access, the vault's own definition and sub-agents across formats.
`tests/agent-definitions.test.ts` covers the three definition formats.

Real Claude Code 2.1.295 and Codex 0.160.0 passed `npm run test:your-ai` in
standard mode. Each vault's `AGENTS.md` and Beta's own `vault-agent` definition
were followed, and each CLI used a sub-agent defined in the other's format.
OpenCode, Pi and Hermes Agent were not run with real models.
