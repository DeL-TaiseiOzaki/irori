# irori 0.2.94 preview 1 — A vault chooses its layers

- A vault now chooses which layers it has
  ([ADR 070](../decisions/070-a-vault-chooses-its-layers.md)). In
  **vault の設定 → 層**, **この vault が持つ層** turns Knowledge and Contents on
  or off; every vault has Schema. Schema + Knowledge + Contents is a knowledge
  base with its materials (what every vault was, and still is by default),
  Schema + Knowledge is notes alone, and Schema + Contents is a workspace for
  code or other work with no notes. irori names no kind of vault: the
  combination is the person's.
- A layer left out is not shown in the vault panel, the vault beside, the home
  or the overview, takes no new notes or connections, and is not described to
  the vault's agent. No file moves, and choosing the layer again brings it back
  as it was. Without Knowledge, the vault's files outside Contents show with
  Schema, whose section opens on its file view.
- Contents is left out only once the vault's folders and repositories are
  disconnected; irori says so otherwise.
- Agents make the same choice with `irori set <vault> --layers schema,contents`,
  and `irori list` says which layers a vault left out.
- The choice is `layers` in the vault's `.irori/scope.json`. A vault that
  declares none has all three, so existing vaults are unchanged; an earlier
  irori ignores the field and shows all three.

Not included: code kept at a vault's own top level shows under Schema, not
Contents. Contents holds connected folders and GitHub repositories; the vault's
root as its contents folder is a separate request.
