# irori 0.1.35 — Edit and add to Google Drive folders

Connected Google Drive folders are no longer read-only. Open a file in a
connected folder, edit it and it is saved to Drive; add a note to a folder with
the **+** beside it in the sidebar, or press **フォルダを開く** in the connection
dialog to add other files with Explorer or Finder. Agents working in a KB can
change the Drive folders connected to its materials as well.

- **What you need to do once.** Accounts added before this version were allowed
  to read only. In the connection dialog, press **書き込みを許可** on the account
  and sign in again; Google asks you to allow irori to see, edit, create and
  delete your Drive files. Your connections stay as they are. Folders connected
  before this version are still read-only: press **編集できるようにする** on each
  one you want to edit. New connections are editable unless you untick the box.
- **How saving works.** A saved file is kept on this device for a moment and
  uploaded to Google Drive automatically, as a new version of the same file, so
  Drive's version history and sharing are kept. The dialog shows how many
  changes are still waiting. If you close irori while changes wait, it asks
  whether to wait; if you do not, they are uploaded the next time that folder is
  connected.
- **Read-only folders.** Any connection can be switched back to read-only.

## Installing

**Windows 11 x64:** download `irori-0.1.35-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.35-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally. Keep irori in **アプリケーション**:
the in-app update replaces the app where it is.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Tests check
the mount options for editable and read-only connections and for an account
that may only read; that saving writes the same file in place, keeps a draft
until then and refuses a stale save; that notes are added without replacing a
file; that waiting uploads are counted and keep their folder connected; and
that signing an older account in again asks for write access and keeps it.

## Remaining boundaries

Passing CI is not acceptance on an installed device: editing a real Drive
folder still needs trials on Windows 11 (WinFsp) and the Mac. irori cannot yet
rename, move or delete Drive files itself, or paste images into a Drive note.
If someone changes the same file elsewhere, the last save wins; Drive keeps the
earlier version in its history. If an upload is refused, for example in a
folder shared with you view-only, the waiting count stays up without a reason.
