# irori 0.1.19 — Windows and Mac preview, skills that say who they are for

A knowledge base can carry its own skills for agents. Until this preview they
were one flat list that simply vanished when removed, and nothing said whether
an agent would find them on its own. An installed 0.1.18 or earlier on either
platform is offered this by **更新を確認**.

## What changed

**A skill can say who it is for.** A skill may name its roles and projects in
its front matter. When any skill in a knowledge base does, the composer shows
**役割** and **プロジェクト** beside the skill list, and choosing one narrows the
list to the skills for it plus those meant for everyone. The choice is kept on
this device for that knowledge base; nothing is written into the knowledge
base.

**A retired skill says why it left.** A knowledge base can replace a skill's
`SKILL.md` with a `RETIRED.md` that records when, why and what replaces it.
irori then shows that under the composer, and a request that still names the
skill stops with that reason instead of an unknown-skill error. No agent picks
up the retired file as a skill.

**到達確認 shows how far each skill reaches.** For every skill, the table says
whether Codex, Claude Code, OpenCode and Pi would find it by themselves when
started in the knowledge base, and whether a personal skill of the same name in
your home folder would take its place. irori still hands the chosen skill to
whichever agent you use; this is about what an agent finds without irori. Only
names like `~/.claude/skills` are shown, never a full path on your machine.

## Installing

**Windows 11 x64:** download `irori-0.1.19-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.19-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests cover roles and projects, the retirement file
and the ways it can be written wrongly, a retired name refused with its reason,
the reach check against a disposable home folder, and the per-knowledge-base
choice. An Electron suite narrows the list by role, shows a retirement, opens
the reach table and checks that no full path appears and that the knowledge
base gains no file.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The reach table follows each agent's documentation for the versions named in
[the skills notes](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/SKILLS.md);
it does not ask the installed agent, and a newer version may look elsewhere.
Company-wide skill folders are not examined. One role and one project can be
chosen per knowledge base. The recommended template does not yet write
retirement files or roles itself. Google connections remain read-only. Drive
uploads, real OpenCode and Pi model turns, Developer ID signing with
notarization, and cross-device history remain separate work.
