# irori 0.2.60 preview 1 — every Schema setting reaches every CLI

What you set under **設定 → Schema** now reaches every CLI agent irori runs:
Claude Code, Codex, OpenCode, Pi, Hermes Agent and the Antigravity CLI. This
covers the shared Schema, each vault's and the irori agent's
([ADR 057](../decisions/057-every-schema-setting-reaches-every-cli.md)).

- **Rules.** A vault's rules, and the irori agent's, used to reach Claude Code
  alone. Every other CLI now hears them in the request, as it already heard the
  shared rules.
- **Hooks.** Hooks used to run on Claude Code alone. irori now runs the shared
  hooks and a folder's own for every other CLI, with Claude Code's meaning:
  - Before a tool runs, a hook can stop it or change its input.
  - After a tool runs, a hook's words reach the agent.
  - SessionStart and UserPromptSubmit add context to the request or stop it.
  - A Stop hook can keep the turn going.
  - SessionEnd and Notification hooks run as well.
  - Where a CLI cannot run an event (Hermes Agent cannot stop a tool before it
    runs), irori asks before the run. The Rules and Hooks sections of the
    settings now say how each reaches every CLI.
- **Delivery.** irori used to count the shared Schema as heard as soon as a
  session existed. A first instruction that failed or was stopped could then
  leave the agent with only a line saying it had been told. Now a session counts
  as having heard it only once the CLI has answered. After the CLI compacts a
  session, everything goes whole again. On Hermes Agent and the Antigravity CLI,
  which do not say when they compact, it goes whole every time.
- **AGENTS.md:**
  - Codex keeps the whole AGENTS.md: 1 MiB instead of 32 KiB.
  - Claude Code reads AGENTS.md even where a CLAUDE.md is present.
  - Where a CLI does not load an AGENTS.md, or loads only part of it, irori
    gives it or names it. This covers a knowledge folder's AGENTS.md, files that
    hide AGENTS.md, and a Hermes session that began with an older copy.
- **Skills.** Pi now gets a vault's skills and the shared ones whether or not
  the project is trusted. Hermes Agent hears them listed.

## Verification

`npm run build`, `npm run format:check`, `npm test` and `npm run test:ui` pass.

- **New `tests/schema-reach.test.ts`.** Protocol stand-ins for every CLI check:
  - rules as words;
  - nested instructions and Pi's `--skill`;
  - a compaction making the next request whole;
  - Pi's and OpenCode's hook scripts denying a call and adding feedback;
  - Stop continuation and UserPromptSubmit;
  - Hermes feedback and the question before an unrunnable hook;
  - Codex's hooks, trusted by hash (checked against Codex's own test vectors),
    with a refused turn no longer counted as heard;
  - the Antigravity CLI's folder of hooks, and its stop when the hooks did not
    load;
  - Claude Code's AGENTS.md setting.
- **New `tests/schema-hooks.test.ts`.** It checks Claude Code's hook semantics.

No real CLI was run; the stand-ins follow each CLI's source or documentation.
That the Antigravity CLI reads hooks from an added folder is inferred from its
documentation. Not tried on Windows.
