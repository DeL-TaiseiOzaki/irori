# irori 0.1.66 — repositories inside a hibachi as submodules

- A hibachi can hold other GitHub repositories as submodules. **その他 →
  submodule を追加…** in Changes clones one into a new folder of the hibachi.
- Once a hibachi has submodules, a picker in Changes chooses the hibachi or a
  submodule. Each submodule commits, pushes, pulls and shows its history on its
  own; the hibachi records which commit each submodule is on.
- Pulling the hibachi moves its submodules along when they have nothing
  uncommitted. Cloning a hibachi from GitHub fetches its submodules, and one not
  fetched yet shows as 未取得 with **取得**.

See [ADR 022](../decisions/022-submodules.md).

## Verification

New host tests (`git-submodules`) add, edit, commit and push a submodule, fetch
it on a second device on its branch, move it with a pull of the hibachi, leave a
submodule with uncommitted edits in place, and refuse remotes other than the
allowed ones and folders in Contents, Schema or an existing path. A new Electron
suite (`submodules-ui-smoke`) adds a submodule from Changes, commits and pushes
in it, records it in the hibachi and fetches it again from the picker.

Fetching submodules from github.com itself and installed Windows and macOS
builds were not tested.
