# irori 0.1.30 — Updates are found even when GitHub's release list lags

When 0.1.29 was published, GitHub's public release list kept showing the new
release without its files for more than half an hour, although every file had
been uploaded and could be downloaded. An installed irori reads that list, so it
could not see the new version. From 0.1.30, when a newer release is listed
without files, irori asks GitHub for that release's own file list, which was
correct throughout. At most three such requests are made per check, and only
for releases newer than the one installed.

If you have not installed 0.1.29 yet, install 0.1.30 instead. An installed
0.1.28 or earlier cannot update itself; after one manual installation, later
versions arrive with **更新して再起動**.

Publishing changed too: a release now stays a draft until every file is
uploaded, is published half a minute later, and the publication checks that the
public list names its files. The hourly check reads each release's own file list.

Details: [in-app updates](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/UPDATES.md).

## Installing

**Windows 11 x64:** download `irori-0.1.30-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.30-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally. Keep irori in **アプリケーション**:
the in-app update replaces the app where it is.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone, and the
Windows and Mac jobs apply the build's own update file with the platform's
tools. A behavior test covers the lookup, its limit and that older releases
cost no request.

## Remaining boundaries

Passing CI is not acceptance on an installed device. The first real in-app
update, from this version to the next, still needs Windows 11 and macOS 26
devices. Updates are trusted as the website download is, through HTTPS to
GitHub and the release's `SHA256SUMS.txt`.
