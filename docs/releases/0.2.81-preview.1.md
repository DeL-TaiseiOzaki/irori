# irori 0.2.81 preview 1 — Connect folders while an agent runs

- **Reconnecting no longer waits for a run.** While an agent ran in a vault, its
  connection sheet greyed out **再接続**, **取得**, **手元のクローンを選ぶ**,
  **フォルダを選び直す**, renaming and unregistering, so a folder that had come
  loose stayed **未接続** until the run ended. These now work during the run. A
  run keeps the folders it was given when it started, so connecting one takes
  nothing from it.
- **A folder waiting for its drive connects during a run too.** A connection
  showing **フォルダを待っています**, or one whose folder came back with a new
  identity, used to stay unlinked for as long as an agent ran in its vault.
  Now only a Git operation in the vault holds it back.
- **What could change a folder a run was given still waits:** disconnecting a
  connected folder, changing its access, **最新にする** on a repository and
  removing unregistered data. The sheet says so while a run works, and the
  host refuses the first two for a linked folder during a run.
- **The irori agent can connect a folder** with `irori connect` while the
  vault's own agent runs.

See ADR 042, amended for this release.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass on Linux under Xvfb.

- `scripts/harness-ui-smoke.ts`, with a fixture agent run held open, connects
  one folder and reconnects another from the sheet, changes the access of the
  one not connected, and checks that disconnecting or changing the access of the
  connected one is refused by the host and greyed out in the sheet.
- `tests/local-folders.test.ts` checks that a waiting folder is linked by itself
  once nothing holds it back, and that `linked` and `isLinked` follow the link.
- `tests/irori-command.test.ts` now expects `irori connect` to link a folder
  while the vault's own agent runs, where it used to expect a refusal.

Not tried on macOS or Windows.
