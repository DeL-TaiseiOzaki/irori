# irori 0.1.7 — Windows and Mac preview, sturdier knowledge base skills

This preview publishes the skill changes merged after 0.1.6. An installed 0.1.6
or 0.1.5 on either platform is offered it by **更新を確認**.

## What changed

**Skill files are read as YAML.** The front matter of a KB's
`.agents/skills/<name>/SKILL.md` is now parsed with a YAML library. Quoted and
folded values, comments and extra structured metadata no longer make a skill
unreadable. irori still uses only `name` and `description`, and a package that
cannot be read is still named under the composer. The size limit is 16 KiB
counted in UTF-8 bytes, so a skill written in Japanese is measured the way it is
stored.

**The picker shows what a skill is for.** Each skill's description appears
beside its name.

**Instructions that point at other files work in every agent.** When a skill's
instructions refer to a file by a relative path, irori tells whichever of Codex,
Claude Code, OpenCode or Pi is running to resolve it from that skill's own
folder. Your note, any selected sources and the skill are placed before your
request, and your own words stay last.

**A linked skill folder is reported.** A skill folder that is a link to somewhere
else is named as a problem instead of silently missing from the list.

**Refreshing is steadier.** The skill list is reread after a run finishes
without clearing the picker in the meantime, and switching to another knowledge
base clears the chosen skill at once.

The package now bundles the `yaml` library, credited in the third-party notice.

## Installing

**Windows 11 x64:** download `irori-0.1.7-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.7-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Skills are chosen per turn from a flat list, with no search and no per-skill
argument, and an agent is not offered them to invoke on its own. Google
connections remain read-only. Drive uploads, real OpenCode and Pi model turns,
Developer ID signing with notarization, and cross-device history remain separate
work.
