# irori 0.2.21 preview 1 — the work folder opens in Contents, and links into it open

- A vault's work folder shows in Contents as `work`, beside its connected
  folders, instead of 未接続. Its files open and can be edited, moved and
  added to there. A work folder chosen elsewhere on this device shows there
  in the same way.
- A path in an agent's reply to a file in the work folder opens it, by its
  place in the vault (`…/contents/work/…`), by the chosen folder's own path, or
  by name.
- A path to a connected folder's real place opens when macOS gives the folder's
  name decomposed (such as マイドライブ) and the reply writes it composed.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/work-folder-contents.test.ts` covers the default folder beside a
connection (listed, read, saved, a folder added, the folder itself not moved, a
link inside refused, a reply's path and a bare name), a folder chosen outside
the vault (listed, read, its path and the tail of one), a folder chosen inside
the vault, and a connection named `work`. `tests/path-links.test.ts` covers a
decomposed folder name. Not tried on macOS or Windows, or with a real CLI's run.
