# irori 0.2.70 preview 1 — words that match what irori does

Two texts still described how irori worked before 0.2.34 and 0.2.26.

- `irori help` and the refusal of `irori call` said that the irori agent hands
  work to a vault agent only on Pi, Hermes Agent or the Antigravity CLI, and
  should use the vault's sub-agent elsewhere. Since 0.2.34 `irori call` works on
  every CLI, for the vaults of the workspace the request was sent in
  ([ADR 050](../decisions/050-vault-agents-and-their-sub-agents.md)). Both now say so, and
  the refusal, which comes only when a request hands no vault, says what to do
  instead. The irori agent's `write-routine` skill likewise hands a vault's
  routine to that vault's agent with `irori call`.
- **設定 › エージェント › 共通** described the **共通 Schema** as instructions and
  skills. It also holds rules and hooks that reach every agent
  ([ADR 048](../decisions/048-shared-schema-settings-and-irori-agent-files.md)); the description says
  so, and that its hooks run beside a folder's own.

A standard skill already in the irori agent's folder keeps the words it was
written with; nothing in it changes how the hand-off works.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass on Linux.
`tests/prompts.test.ts` checks that the help of `irori call` and its refusal
name no CLI as left out; it fails on 0.2.69.
