# irori 0.1.15 — Windows and Mac preview, the notes that link here

0.1.14 made a link between notes something you can follow. This preview adds
the other direction: which notes point at the one you are reading. An installed
0.1.14 or earlier on either platform is offered this by **更新を確認**.

## What changed

**リンク元 lists the notes that link to this one.** The button in the note's
toolbar lists every other note in the same knowledge base with a link that leads
here, each with its line and the text around the link. Choosing one opens it,
saving the note you were writing first, as any open does.

**A link counts the way it is followed.** A relative link is resolved against the
note that carries it, so `../wiki/x.md`, `./x.md#見出し`, `<x y.md>` and a
percent-encoded name all count. A link inside inline code or a fenced code block
does not: a note explaining how to write a link is not linking. A Japanese file
name matches whether the Mac stored it composed or decomposed.

**It reads when you ask.** There is no index yet, so the list is made by reading
the knowledge base's Markdown when you press the button, within the same limits
as **KB内を検索**, and it says so when a limit or an unreadable file left it
incomplete. Nothing is written.

## Installing

**Windows 11 x64:** download `irori-0.1.15-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.15-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

For this change, behaviour tests cover each way a link destination is written —
relative, with a heading, bracketed, percent-encoded and escaped — code spans
and fenced code, composed and decomposed Japanese names, a line crafted to stall
the reading, the knowledge-layer exclusions, the note's own link, an incomplete
scan and the validated request the window has to use. An Electron suite lists
the note linking to a page, opens it from the list, and shows the answer for a
note nothing links to.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

A note chosen from **リンク元** opens at its top rather than at the link. Links
in frontmatter are not read, the list is not kept up to date while it is open —
**もう一度調べる** reads again — and no link is rewritten when a note moves.
Source view does not follow links, a heading after `#` is not scrolled to, and a
missing page is not offered for creation. Google connections remain read-only.
Drive uploads, real OpenCode and Pi model turns, Developer ID signing with
notarization, and cross-device history remain separate work.
