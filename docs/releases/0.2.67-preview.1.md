# irori 0.2.67 preview 1 — relations are picked, and a new page starts from a type

- In a page's properties, **関係** is now edited in place. Each relation is a
  name and a target: the name is chosen from the relations the vault declares
  for a page of this type, and the target from the pages of the types that
  relation points at, shown with their titles, or typed as a URL when the
  relation points at one. **＋ 関係を追加** adds one; it is written to the page
  once it has both a name and a target.
- A name the vault does not declare, or one a page of this type may not state,
  stays as written and is marked, as an undeclared type already was. Nothing is
  dropped.
- **ノートを作成** asks for the type when the vault declares types. The new page
  starts with that type, its title, you as its last change, and the properties
  the type requires, empty and marked as required. **種類なし** makes a plain
  note as before.

Both come from the vault's ontology, `.property/property.json`
([ADR 060](../decisions/060-the-ontology-is-the-declaration.md),
[ADR 015](../decisions/015-page-properties.md)). A vault that declares nothing
sees no change.

## Verification

`npm run build`, `npm run format:check` and `npm test` pass on Linux. New tests
cover the text a typed page starts from, an undeclared type refused, the link a
target is written as, and the list of pages a relation can point at.
`scripts/properties-ui-smoke.ts` picks a relation and starts a page from a type
in a real Electron under Xvfb. Not seen on Windows or macOS, and not tried
against a vault in real use.
