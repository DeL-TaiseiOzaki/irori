# irori 0.1.11 — Windows and Mac preview, a smaller application

This preview carries the same features in less than half the code the last one
shipped to the window. Nothing was removed from the product: what left the
package was never reachable. An installed 0.1.10 or earlier on either platform
is offered it by **更新を確認**.

## What changed

**The maths engine is gone, and it was never on.** The rich editor is built on
Crepe, whose LaTeX support irori turned off on the first day. That switch is
read while the application runs, long after the code is packaged, so KaTeX and
its fifty-nine font files travelled in every build — 1.4 MB for a feature no
menu offered. The editor is now assembled from the features it actually uses, so
they are not there to begin with.

**A reply's Markdown renderer loads with the first reply.** It is the single
heaviest thing a session that never opens the assistant used to load.

**Source control, connections, search and the knowledge panel load when
opened.** Each is a panel most sessions never open.

**The mark is drawn at the size it is shown.** The application displayed a
1254-pixel-square image at 40 and 80 pixels. The window, the dock and the
installers still use the full-resolution file.

**Measured.** The packaged front end falls from 6,946,180 to 3,828,368 bytes and
from 183 files to 131. What the window loads before anything is opened falls
from 818.7 kB to 589.4 kB, 258.7 kB to 187.2 kB compressed. The editor's own
code falls from 1,595.5 kB to 1,253.0 kB, 519.6 kB to 414.7 kB compressed.

## Installing

**Windows 11 x64:** download `irori-0.1.11-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.11-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

The thirteen Electron UI suites cover the surfaces this change touches: rich and
source editing, image paste, undo and redo, the block menu, the source-control
panel, search, the knowledge panel and the assistant's rendered replies.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The installer itself is not smaller in proportion: the front end is about one
percent of the package, and the rest is the agent SDK's platform binaries and
the bundled rclone. Memory in use has not been measured against the earlier
build. Syntax highlighting inside code blocks still carries every language
CodeMirror ships. Google connections remain read-only. Drive uploads, real
OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
