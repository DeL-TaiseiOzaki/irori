# irori 0.1.22 — Windows and Mac preview, Pi and OpenCode hear about your lines too

Since 0.1.20, Claude Code has been told when an edit it is about to make would
change lines a person wrote. This preview tells Pi and OpenCode the same thing.
An installed 0.1.21 or earlier on either platform is offered this by
**更新を確認**. 0.1.20 and 0.1.21 were not published on their own, so an
update from 0.1.19 also brings what they added, summarised below.

## What changed

**Pi and OpenCode are told before they change a person's lines.** When Pi or
OpenCode is about to edit or write a note in a way that changes lines a person
wrote or revised, irori tells it which lines, quoted, as information and not as
an instruction. Neither CLI lets irori add a word to an edit and let it run, so
irori holds that one edit with the notice; the agent can make the same edit
again and it goes through. An edit that leaves the person's lines alone is not
held and is not told anything.

irori does this through each CLI's own extension mechanism, with a small script
kept in irori's own data folder and never in your knowledge base.

**Codex is not told at edit time.** Codex reads its hooks only from your home
folder or the project's own settings and asks you to trust each one first, and
irori writes neither. Codex still receives your lines when you tick
**人の行を伝える**.

## Also in this preview, from 0.1.20 and 0.1.21

**irori marks the lines a person wrote or revised** (0.1.20). A line counts
when you typed it or changed any part of it. Above the note irori shows
**人が書いた・直した行** with their number, and source view marks each one. When
you save, only the lines you introduced are marked; what an agent wrote, or what
arrived by pull or from another editor, is not. Claude Code is told before it
edits one of those lines, and any agent is told when you tick **人の行を伝える**
in the request box. The earlier display of how many lines each agent wrote is
gone, and marks recorded by earlier previews are not carried over.

**Those lines travel with your commits** (0.1.21). A commit made in the
ソース管理 panel carries a Git AI Standard note under `refs/notes/ai` naming
them under the key derived from your Git name and email; Push sends the notes,
and Fetch and Pull bring in other people's. Lines named in the notes count as a
person's on every computer. GitHub's squash and rebase merge buttons drop the
notes, and commits made outside irori carry none.

Details: [0.1.20 notes](0.1.20-preview.1.md), [0.1.21 notes](0.1.21-preview.1.md).

## Installing

**Windows 11 x64:** download `irori-0.1.22-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.22-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests drive irori's actual Pi and OpenCode scripts
through protocol stand-ins: an edit that would change a person's line is held
once with the lines quoted and runs when repeated, an edit to an agent's line is
not held, the scripts live in irori's data folder, and nothing is written into
the knowledge base. Further tests cover how each CLI's edit and write inputs are
applied.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

How Pi's and OpenCode's models respond to a held edit was not observed in a real
session, and OpenCode's loading of the script was checked only through a
stand-in. Pi applies edits loosely, so an edit only that looseness lets through
is not noticed. Codex is not told at edit time.
