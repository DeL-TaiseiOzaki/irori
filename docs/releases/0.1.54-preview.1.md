# irori 0.1.54 — page properties above the note

A knowledge page's frontmatter used to open as a block of YAML at the top of the
note. It now opens as properties, as in Notion: the title and description as
the page's heading, and one row per property below them.

## Properties

- **Every Markdown page in the knowledge layer** shows its properties above the
  body. A folder's `index.md`, files in the schema layer and files in contents
  open as before. irori does not look at folder names.
- **The knowledge base says which properties exist.** When it has
  `.property/property.json` (irori-templete provides one), types and states are
  chosen from a list, the keys a page's type requires are marked **必須** when
  empty, and choosing a type adds the keys that type requires. Without the
  file, every key still shows in a row that fits its value.
- **Edits change only what you changed.** The file keeps its YAML frontmatter;
  a changed value is rewritten in place, and comments, key order, quoting, the
  one-line `{ by: ..., at: ... }` form and keys irori does not know stay as
  written. Opening a page and closing it changes nothing.
- **Who changed the page last is recorded when you save.** A property the
  declaration marks `"auto": "last-change"` (`generated` in irori-templete)
  becomes `human:<your Git email before the @>` and the current time. Set
  `git config user.email` in the knowledge base if the page says it is missing.
- **YAML で編集** shows the frontmatter as text and back. Frontmatter that does
  not parse opens that way with the reason, and irori leaves it as it is.
- **＋ プロパティを追加** adds a declared property, another name, or, on a page
  without frontmatter, the keys every page requires.

Sources, relations and verification are listed but edited as YAML for now;
choosing pages and files for them comes next.

## Installing

**Windows 11 x64:** download `irori-0.1.54-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.54-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

- The full build, unit tests (the frontmatter round trip: comments, flow
  collections, block lists, unknown keys, BOM and CRLF, broken and duplicate
  keys, the last-change stamp) and the Electron UI journeys passed, including a
  new one over a disposable knowledge base shaped like irori-templete's.

## Remaining boundaries

- Pickers for `resource`, `sources` and `relations`, **確認済みにする**, tag
  suggestions from the knowledge base, and starting a new page from a type
  ([ADR 015](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/decisions/015-page-properties.md)
  stages 2 and 3).
- Japanese input (IME) in the property fields has not been tried on an installed
  Windows or Mac build.
