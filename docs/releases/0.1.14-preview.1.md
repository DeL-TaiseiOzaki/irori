# irori 0.1.14 — Windows and Mac preview, links between notes

A knowledge base is pages that point at each other. Until this preview irori
showed those links and did nothing with them, so reading one meant finding every
next page in the explorer. An installed 0.1.13 or earlier on either platform is
offered this by **更新を確認**.

## What changed

**Ctrl/Cmd + click on a link opens what it points at.** Links between pages are
ordinary relative Markdown links — `other.md`, `../decisions/2026-09-21.md` —
which is how the recommended knowledge-base template writes them, since a page
is identified by its path. A plain click still places the cursor in the link's
text, because in an editor that is what clicking a link is for.

**The note you are writing is saved first.** Following a link uses the same path
as opening a note from the explorer, with the same conflict handling, and a
running agent or a queued instruction still refuses to have the space changed
underneath it.

**A page that does not exist yet says so.** The note stays open and the missing
path is named. In a knowledge base a link to an unwritten page is an ordinary
state, not an error.

**A link cannot reach further than the explorer can.** An absolute path, a `..`
above the knowledge base, a `file:`, `javascript:`, `data:` or `mailto:` link, a
folder, a symlink that leaves the knowledge base, a path inside another
registered KB and anything under `contents/` are each refused with a reason. A
`https://` link opens in the browser as before.

## Installing

**Windows 11 x64:** download `irori-0.1.14-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.14-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

For this change, behaviour tests cover what each form of link resolves to,
including every refusal, a symlink that leaves the knowledge base, a link into
another registered KB and the validated request the window has to use. An
Electron suite follows a link down into a folder and back out of it, reports a
missing page, carries unsaved text through a link by saving it first, and checks
that a plain click opens nothing.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Source view does not follow links; the gesture is the rich editor's. There is no
list of the pages that link **to** the one you are reading. A heading after `#`
is not scrolled to. A missing page is not offered for creation, and no link is
rewritten when a note moves. Google connections remain read-only. Drive uploads,
real OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
