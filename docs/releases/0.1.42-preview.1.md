# irori 0.1.42 — Your AI: one agent that hands work to each brain

The Overview now has **your AI** (あなたの AI): your own agent, working across
the brains of a workspace. You ask it for something that spans your brains; it
splits the work and hands each part to that brain's AI, which reads the
brain's own Schema first. It then tells you what each brain did.

- **Set it up once.** Open **全体** (Overview); beside the map, **あなたの AI** offers
  **あなたの AI を用意する**. irori creates your AI's folder, `~/irori/you` on this
  device, with a short `AGENTS.md` and a `brain-agents` skill. It never writes
  over files that are already there.
- **Each brain gets its own sub-agent.** Your AI keeps a definition for each
  brain in its folder (`.claude/agents/<brain>.md`). The definition tells the
  sub-agent to read that brain's `AGENTS.md` and skills, work only inside that
  brain, and report what it changed. Your AI writes these definitions itself
  when you ask: open its folder from the orb on the map (**あなたの Schema**) and
  press **あなたの AI に定義を更新させる**.
- **See the hand-offs.** Your AI's replies show a task list: which brain got
  what, and whether it is working, waiting for your permission, or done. Each
  brain's report follows. On the map, a line with a moving spark runs from
  your AI to each brain it is working with.
- **Answer from the Overview.** When a brain's sub-agent wants to change a file,
  the request appears in your AI's panel, marked with the brain it comes from.
- **Brains stay in their lanes.** irori lets your AI write only in its own
  folder, and each brain's sub-agent only inside its own brain. Work that
  needs a brain goes through that brain's sub-agent. While your AI works, the
  brains it was given wait: their own AI, Git and settings resume when it
  finishes.
- Your AI runs on **Claude Code** for now, with its standard permission mode.
  Codex follows later.

**Fixed:** a permission request could appear as already ended when Claude Code
reported the tool call after asking. That affected ordinary brain runs too.
Requests now end only when they are answered, declined or cancelled.

## Installing

**Windows 11 x64:** download `irori-0.1.42-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.42-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

Unit tests cover the sub-agent names, the write rule, the folder and its
starter, and a full hand-off through a Claude Code protocol fixture: brains held
during the run, each step, request and report attributed to its brain, your
AI's own write in a brain refused, and a background hand-off run in the
foreground. A new UI test does the same in the app, from setup to the report and
the definitions. A separate real Claude Code run (2.1.280) confirmed the parts
only a model can: definitions load from your AI's folder, the sub-agent follows
its brain's `AGENTS.md`, the write rule holds for both a sub-agent and your AI,
and a resumed conversation still delegates.

## Remaining boundaries

Passing CI is not acceptance on an installed device. A brain's sub-agent is not
quite the brain's own AI: it works from your AI's folder and settings and
reaches the brain through the definition, so a brain's own Claude Code settings
do not apply to it. Terminal commands are not bounded by brain; Claude Code asks
you for them as usual. Every free brain of the workspace waits for the whole of
your AI's request.
