# irori 0.2.95 preview 1 — A vault's own files can be its Contents

- A vault of Schema and Contents now shows its own files in Contents, where
  0.2.94 showed them under Schema
  ([ADR 071](../decisions/071-a-vaults-own-files-in-contents.md)). A repository
  of code is a vault as it is: its files open and save in place, take new
  files, folders and notes, are renamed, moved, copied and sent to the trash,
  and the Changes view stages and commits them. A vault's own files are those
  outside Schema and its contents folder; they are Knowledge when the vault has
  that layer, Contents when it has Contents and no Knowledge, and Schema when
  it has neither.
- The contents folder is unchanged: folders and GitHub repositories from
  elsewhere are connected there, and Git ignores it. It shows below the vault's
  own files under its name.
- A vault with both layers can keep code beside its notes: **vault の設定 → 層**
  has **vault 直下のファイルも** on the Contents row. Knowledge is then its
  named folder alone; the choice is not offered while the knowledge folder is
  the vault's root. Agents use `irori set <vault> --own contents` (or
  `--own knowledge`), and `irori list` says `own files in Contents`.
- Own files stay the vault's own: a new entry, a rename or a move that would
  land in Schema, Knowledge, the contents folder, a connected folder or another
  vault is refused, and a folder holding one of those is neither moved nor
  deleted. Moves and deletions wait for the vault's runs, as those of knowledge
  do.
- The vault agent is told that Contents is the vault's own files, changed in
  place and kept in its Git history.

Not included: search still covers knowledge alone, so text in these files is not
found; note tools (properties, links that follow a move) apply to knowledge
only.

## Verification

`npm run build` and `npm run format:check` pass. `npm test` passes except
`tests/ssh-config.test.ts` "what is shown of each host is what ssh itself
resolves", which fails on the shared Linux host without this change too.
`tests/vault-own-contents.test.ts` covers the rule, listing, saving, new
entries, moves, the trash, the refusals and connections beside own files;
`tests/git.test.ts` commits an own file while the contents folder stays blocked;
`tests/vault-layers.test.ts` and `tests/irori-command.test.ts` follow the rule.
`scripts/vault-layers-ui-smoke.ts` runs in pull request CI on Linux under Xvfb;
the development host has no display. Not tried on macOS or Windows, and not with
a real CLI agent.
