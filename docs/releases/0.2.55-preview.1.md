# irori 0.2.55 preview 1 — agents see a connected folder as one folder

- A folder connected in contents reaches an agent by two names: its link in the
  vault, `contents/<name>`, and its own place on this computer, which the CLI
  is allowed into. Agents are now told the two are the same folder, to work
  through the link, and to write the link's path in notes and replies rather
  than a path that only works on this computer.
- The search advice for connected folders now also covers `find`, which lists
  only the link unless its path ends in `/` or it follows links, and says that
  a link searched by its path that shows nothing really holds nothing there.
- The irori agent, which works in its own folder, gets the example as the whole
  path through the vault.

## Verification

`npm run build` and `npm test` pass, with new checks of the wording for vault
agents and the irori agent, a Windows vault's example path, the folders a vault
reports, and a Codex request that names its writable folder as the link's.
Not yet tried with a real CLI turn or on Windows or macOS.
