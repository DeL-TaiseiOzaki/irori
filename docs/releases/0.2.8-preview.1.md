# irori 0.2.8 preview 1 — Workspaces as tabs

Several workspaces can now be open at once, as tabs along the top of the
window ([ADR 037](../decisions/037-workspace-tabs.md)).

- **+** at the end of the tabs, or the irori logo on the rail, shows the start
  screen. A workspace opened there becomes a new tab; one already open comes
  back where it was left: the same vault, note and view.
- Agents keep running in the tabs not on show. A tab shows a dot while an
  agent in its vaults runs or waits for permission.
- Home no longer stops anything. Closing a tab (×) stops the agents only that
  tab has open, after asking. Leaving a tab with a terminal open asks first,
  since the terminal closes.
- The status bar no longer shows the workspace name; the tab does.
- While a workspace is open in a tab, the start screen does not delete it or
  its vaults.

Tabs are not restored after a restart.

## Verification

`npm run build`, `npm run format:check` and `npm run test:ui` pass. `npm test`
passed except one timing test (`git-host-load`, Git child limit), which passed
alone; nothing in it touches this change.
`overview-ui-smoke` opens a second workspace while agents run and wait in the
first, checks that they keep going, cancels closing a tab that would stop one,
and closes a tab that shares its only vault. `tests/workspace-tabs.test.ts`
covers tab order, closing and which vaults a closing tab stops.

Not tried on Windows or macOS.
