# irori 0.1.91 preview 1 — Move in from another tool with the irori agent

Tell the irori agent in irori mode that you are moving in from Obsidian, orca,
an editor or a folder of files. It looks at what you have — vaults and their
settings, projects, synced folders — and asks, a few questions at a time, what
each should become: a hibachi, contents of a hibachi, or left out; where it
lives; which folders are Knowledge and which are Contents; Git and GitHub;
workspaces; daily notes and links. It writes the plan in its folder, waits for
your yes, sets it up and reports what came over and what did not.

Two new standard skills make this possible: **irori-guide**, everything irori
can do and who does each part, and **move-to-irori**, the protocol for the
move. A folder set up earlier gets them from the + on the irori agent's
screen.

The `irori` command does what the hibachi settings and the start screen do:
`irori layer` chooses the knowledge and contents folders (an existing folder
is taken as it is; `--also` makes another folder contents in place), `irori
set` changes the name, category and layer names, `irori workspace` makes and
changes workspaces, `irori disconnect` takes a connected folder out and
`irori remove` takes a hibachi off this computer, keeping its folder unless
`--trash` moves it to the trash. `irori list` now shows layers, connected
folders and workspaces. Decided in ADR 030.

## Verification

`npm run build` and `npm test` pass. Host tests register an Obsidian-like
vault, take its `wiki/` as knowledge and `attachments/` as contents without
moving anything, rename the contents folder, change the name, category and a
layer name, make, extend and leave workspaces, take out a connected folder
while the folder stays, refuse changes while the hibachi's own agent runs, and
remove a hibachi from its workspaces while its folder stays. Not tried with a
real CLI, a real vault or orca's data, nor on Windows or macOS.
