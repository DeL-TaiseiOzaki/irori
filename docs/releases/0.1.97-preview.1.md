# irori 0.1.97 preview 1 — Codex runs no longer stop when a sub-agent finishes

A conversation with the irori agent or a hibachi agent on Codex no longer stops
when one of its sub-agents or forked threads finishes.

- **The run ends with its own turn.** Codex's app server streams every thread it
  runs on one connection. irori took any thread's `turn/completed` as the end of
  the run, so the first sub-agent to finish stopped the parent and the other
  sub-agents, and the conversation showed as completed. Only the run's own
  thread and turn now end it.
- **Sub-agents' words stay out of the reply.** A sub-agent's streamed reply and
  its tool calls were shown as the parent's. They are now left out; the parent's
  sub-agent calls and their results still show.

Questions and approval requests from a sub-agent are still shown and answered.

## Verification

`npm run build` and `npm test` pass.

- A protocol fixture spawns a sub-agent whose thread replies and finishes its
  turn while the parent's turn goes on. The run ends only with the parent's
  turn, and the reply holds only the parent's words. Without the change the
  same fixture ends the run at the sub-agent's end, with its words in the reply.

Not tried with a real Codex CLI.
