# irori 0.1.27 — Choose agent access and recover retained cloud preparations

The conversation controls now let you choose native access behavior or full
access for Codex, Claude Code and OpenCode. Each option describes the actual
provider behavior. Pi continues to use its native settings and does not claim
to offer standard per-tool approvals. Queued messages retain their selected
mode. Changing mode starts a new native conversation while keeping irori's
display history, so a previously elevated session is not reused under a
different access label.

The startup screen and workspace sidebar now expose retained cloud-send
preparations across this device, including after their connection or workspace
registration has been removed. Restore an exact retained version into a new
local file without overwriting existing bytes. A damaged record does not hide
other recoverable preparations.

Google connections still request read-only access. Agent full access does not
grant Google write permissions or send retained preparations. Writable Google
delivery, native device acceptance and the VS Code extension runtime remain
separate work. This preview does not yet execute VS Code extensions.
