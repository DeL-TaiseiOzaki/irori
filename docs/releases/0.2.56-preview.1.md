# irori 0.2.56 preview 1 — send a queued instruction now

- Each instruction waiting in a conversation's queue has **今すぐ送る** beside
  取消, in a vault agent's column and in the irori agent's. It sends that
  instruction without waiting for the run to end, ahead of the others.
- On Claude Code and Codex the running turn takes it at its next step and goes
  on without stopping, as those CLIs do with words typed while they work. The
  log shows the instruction where the run took it.
- An instruction with attached files, a skill, a `/` command, or another model,
  level, access or set of materials than the run was started with needs a
  request of its own: the run stops and it starts at once. The same happens on
  Pi, OpenCode, Hermes Agent and the Antigravity CLI, which take no words while
  they work. The rest of the queue goes on afterwards.
- A routine's step and a vault agent's work handed over by the irori agent are
  not interrupted this way.
- Every Claude Code turn now uses the Agent SDK's streaming input; the request
  reaches Claude Code as before.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass, with new protocol
fixture tests of a Codex `turn/steer`, a Claude Code mid-turn message, a run
that stops for an instruction it cannot take, and the irori mode threads smoke
sending a queued instruction now in the irori agent's column and in a vault's.
Not yet tried with a real Claude Code or Codex turn.
