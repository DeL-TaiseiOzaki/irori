# irori 0.1.13 — Windows and Mac preview, a much smaller download

This preview is the same application as 0.1.12 with a large piece of dead weight
removed: executables that shipped in every installer and that irori never ran.
An installed 0.1.12 or earlier on either platform is offered it by **更新を確認**.

## What changed

**The download no longer carries a second copy of Claude Code.** irori drives
Claude Code through Anthropic's Agent SDK, and that SDK brings its own complete
Claude Code executable — about 220 MB — for each platform it supports. irori has
never used it: it runs the `claude` you installed yourself, with your own
authentication, settings and skills, which is the whole point of the local CLI
model. The unused copy is now dropped while packaging.

**And it no longer carries terminal binaries for other operating systems.** The
terminal is built on node-pty, whose package includes prebuilt binaries for
Windows and macOS regardless of where it is installed. Only the one matching
your system can load; the others are removed.

**Measured.** On Linux x64, where npm installs two of those Claude Code binaries
at once, the packaged application falls from 994,253,996 to 500,345,370 bytes and
its archive from 548,291,885 to 115,044,075. Windows and Mac carried one such
binary rather than two, and the build the packages are made from now uploads
430,525,885 bytes for Windows where 0.1.12 uploaded 638,848,363, and 366,045,824
for the Mac where it uploaded 565,979,157 — each of those carries two compressed
copies of the application, so the download you take is smaller still. The exact
installer bytes are in the **Exact package** facts below.

Nothing about how irori works changed. If `claude` is not installed on your
system, irori reports that it cannot find it, exactly as it did before.

## Installing

**Windows 11 x64:** download `irori-0.1.13-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.13-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

For this change specifically, each package job asserts that no Claude Code
binary and no foreign terminal prebuild is in the archive, loads the Agent SDK
from the packaged application, and types a command into the real terminal that
writes a Japanese filename — on Windows that exercises the one prebuilt binary
the package still carries.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

irori needs the CLI you want to use to be installed and authenticated on your
system; it does not install one for you, and this release does not change that.
The download is still large: the bundled rclone and the Electron runtime are
most of what is left. Google connections remain read-only. Drive uploads, real
OpenCode and Pi model turns, Developer ID signing with notarization, and
cross-device history remain separate work.
