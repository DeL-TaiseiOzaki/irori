# irori 0.1.2 — Google connection testing preview

This unsigned Windows x64 preview includes the distributor's Google desktop client configuration, enabling the Google account connection flow. Versions 0.1.0 and 0.1.1 remain unconfigured; installing this new build is required. Successful Google consent and native mounts still need the owner's device trial.

## Download and try Google Drive

1. Close the earlier irori version and install `irori-0.1.2-windows-x64-Setup.exe`. This is an unsigned testing preview; Windows may show the same unknown-publisher/SmartScreen prompt as before.
2. Install [WinFsp](https://winfsp.dev/rel/) for Windows filesystem mounting. The irori connection dialog links the official download and can recheck installation. rclone is bundled; Node.js/npm and a separate rclone installation are unnecessary.
3. Open a test workspace and choose **接続** in the workspace's **Google Drive** area, or the header's **クラウド接続**. This flow is independent of KB registration; per-KB contents controls manage legacy connections.
4. Enter an account name and choose **Googleアカウントを追加**. Complete Google's permission screen in your system browser. If the Google project is in testing, use an account registered as a test user in that project.
5. Select My Drive or a shared drive, choose the folder and its local name, and register it. Try reading a file, reconnecting after restart and adding a second account. Report the exact error if any step fails; do not post credentials, OAuth URLs or private documents.

The app currently requests only `https://www.googleapis.com/auth/drive.readonly`. The owner declared broader Google permissions for future writing; those console declarations do not change the app's current request or implement uploads. Google consent covers viewing/downloading all Drive files; the irori folder chooser narrows the selected connection, not the account-wide OAuth grant. Cloud writing, durable upload/recovery and re-consent remain future implementation work. [Google Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

Google's testing mode expires these authorizations, including refresh tokens, after seven days. Production consent/verification is separate from this owner trial. [Google audience documentation](https://support.google.com/cloud/answer/15549945?hl=en).

## Remaining scope and support

The terminal, note editing, Git controls and CSV/ontology display from 0.1.1 remain available. Actual Google consent/refresh/shared-drive mounts, Windows 11 installation/upgrade/IME/native-agent acceptance, signing, provenance and cloud writes remain open. Mac downloads remain unavailable. This continues the owner-authorized Windows testing channel and does not waive [general-release requirements](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/RELEASE-PLAN.md).

Use [GitHub Issues](https://github.com/DeL-TaiseiOzaki/irori/issues) for version/OS/error reports. KB files remain in selected local folders; agent requests may send relevant content to their providers. Google authorizes Drive access through the local rclone process, which stores account tokens in irori's device data. The download site has no app backend or added analytics.
