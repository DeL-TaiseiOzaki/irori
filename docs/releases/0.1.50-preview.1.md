# irori 0.1.50 — the irori agent in the same shape as a hibachi agent

The **irori agent** now works the way a **hibachi agent** does: its Schema is
edited with the same settings, it starts in full access, and it can hand work
to every hibachi agent on every CLI.

## The irori agent's Schema

- Open the irori agent's screen (its orb on the map, or "<CLI> · あなたの
  Schema"). Its Schema is shown as the same settings a hibachi has:
  **指示** (its `AGENTS.md`), **スキル**, **ルール** and **フック**, each with
  **＋** and the same forms, saved as the same files in its folder.
- The folder icon shows the folder as files, read-only, as before. The hibachi
  agent definitions irori writes are listed there and on the right as before.
- While the irori agent is working, its settings wait, as a hibachi's do.

## Full access

- The irori agent starts in **フルアクセス** (full access) on every CLI,
  including Claude Code. The access pill beside its CLI and model switches it to
  the standard mode, as in a hibachi agent's composer.
- On Claude Code, irori still keeps the irori agent's own writes out of the
  hibachis in full access, and each hibachi's sub-agent works inside its
  hibachi.

## Hand-offs on every CLI

- Claude Code, Codex and OpenCode hand work to each hibachi's sub-agent, as
  before.
- **Pi** and **Hermes Agent** now hand work too. irori gives the irori agent a
  `hibachi` command for the request: `hibachi <name> "<task>"` runs that
  hibachi's hibachi agent inside the hibachi and returns its report. The run
  shows in the hibachi's own panel, and the irori agent's list shows the task
  as working, then done or failed. Stopping the irori agent stops it.
- The command uses irori itself to run; nothing else needs installing.

## Names

- There is no "hibachi mode": working in a hibachi is simply working there.
  **irori mode** stays the name of the overview.

## Installing

**Windows 11 x64:** download `irori-0.1.50-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.50-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

- Unit tests cover the Schema settings on the irori agent's folder (only its
  `AGENTS.md` as instructions, links not followed out, hash conflicts), the
  irori agent on Claude Code in full access against a protocol stand-in (its own
  write in a hibachi refused, the sub-agent working without a request), and the
  `hibachi` command: name matching, the launcher, a refused or forged request,
  and a Pi stand-in handing work to a hibachi, whose run is kept in that
  hibachi's conversation.
- The irori agent's Electron smoke adds a rule and a skill through its settings,
  checks they wait while it runs, and hands work on Pi through the command run
  by the app itself.
- The full build, unit tests and Electron UI suites passed.

## Remaining boundaries

- Not yet tried with real Claude Code, Pi or Hermes Agent as the irori agent in
  this version, nor from an installed macOS or Windows 11 app. Whether Pi's and
  Hermes Agent's shell tools keep irori's command available, and whether a tool
  time limit of theirs cuts a long hand-off, is unconfirmed.
- On Codex, OpenCode, Pi and Hermes Agent the hibachis' boundaries are
  instructions, not enforced; only Claude Code's writes are checked.
- Running Claude Code in full access as the administrator (root) is refused by
  Claude Code; use the standard mode there.
