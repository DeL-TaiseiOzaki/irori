# irori 0.1.18 — Windows and Mac preview, search that keeps an index

Every search and every backlink list used to read every note again, so a large
knowledge base was slow and one above 2,000 files was never searched in full.
This preview keeps an index on the device. An installed 0.1.17 or earlier on
either platform is offered this by **更新を確認**.

## What changed

**KB内を検索 and リンク元 answer from an index.** irori keeps the text of each
note, with an index over it, in its own data folder on this device. A repeat
search reads only the notes that changed since the last one. On a test
knowledge base of 15,118 notes, a search that took 5 to 9 seconds now takes
about half a second once the index is built.

**Nothing comes from stale text.** Each request still looks at every note's
size and modification time, and reads again any note that was added, changed,
renamed or removed, whether it was changed in irori, by an agent or in another
editor. Results, line numbers and previews are the same as before.

**Short Japanese words work as before.** A two-character query such as 知識 is
matched against the stored text of every note, and longer queries are narrowed
by the index first. Letter case is ignored for every alphabet, as before.

**Larger knowledge bases are covered.** A request now looks at up to 50,000
files instead of 2,000.

**The index is a cache.** It lives in irori's data folder, never in the
knowledge base, and deleting it loses nothing: the next search builds it again.

## Installing

**Windows 11 x64:** download `irori-0.1.18-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.18-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone — and now one search,
which shows the index working inside the packaged application. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests cover a repeat request that reads no file,
notes modified, added, removed and renamed between requests, one- and
two-character Japanese queries, case beyond ASCII, a damaged index rebuilt,
backlinks answered from the index, and that nothing is written inside the
knowledge base.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The first search on a large knowledge base builds the index and may report that
it could not look at everything; the next search completes it. While that first
build runs, other actions wait up to about a tenth of a second at a time. A
change that keeps a note's size and lands within the disk's timestamp
resolution of the previous one is seen at the next change. The backlink list
still reads the stored text of every note, about 1.7 seconds at 15,000 notes.
Google connections remain read-only. Drive uploads, real OpenCode and Pi model
turns, Developer ID signing with notarization, and cross-device history remain
separate work.
