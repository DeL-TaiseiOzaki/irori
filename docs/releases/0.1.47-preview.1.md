# irori 0.1.47 — No stray error after removing the open workspace

After you removed the workspace that was open on the **ワークスペースを選択**
screen and then opened another one, irori showed "Unknown or ambiguous cloud
owner" in a red bar. Nothing was wrong with your brains or notes. irori was
asking to close the Drive connections of the workspace that no longer existed.
Removing a workspace already unregisters its own connections, so irori now
skips it.

## Error messages

- Opening another workspace after removing the open one no longer shows an
  error.
- When a brain's Drive connection record (`.irori/cloud-mounts.json`) cannot be
  read, the message names the brain. It also says to restore the file from the
  Git history or fix it, instead of showing a JSON parser error such as
  `SyntaxError: Expected property name…`.
- A Drive connection whose brain or workspace cannot be found is now reported in
  Japanese (or English), not as "Unknown or ambiguous cloud owner".

## Installing

**Windows 11 x64:** download `irori-0.1.47-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.47-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

- The owner's report was reproduced in the Electron app:
  1. clone the private mock KB through **GitHub から取得**;
  2. open it in a workspace;
  3. return to the start screen and remove that workspace;
  4. open the brain in a new workspace.
  The failing host call was `cloudConnections` with the removed workspace's ID.
- `cloud-ui-smoke` now removes the open workspace and opens another. It fails
  on 0.1.46 and passes with this change.
- A unit test in `connections.test.ts` covers both messages: a missing owner,
  and a record that is not JSON or does not match the schema.
- The full build, unit tests and Electron UI suites passed.
