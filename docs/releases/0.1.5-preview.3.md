# irori 0.1.5 — Mac preview, launch fixed

The first Mac download could not start. It cleared Gatekeeper and then aborted
immediately, with a crash dialog offering only **ゴミ箱に入れる** and **完了**.
This build fixes that. Windows is unaffected and unchanged in behaviour.

If you already installed the earlier Mac build, replace it with this one.

## What was wrong

From the affected machine, macOS 26.7 on Apple silicon:

```
dyld: Library not loaded: @rpath/Electron Framework.framework/Electron Framework
  Reason: ... code signature ... not valid for use in process:
  mapping process and mapped file (non-platform) have different Team IDs
```

The package was signed with the hardened runtime enabled. The hardened runtime
enforces library validation, which requires every library a process loads to
carry the same Team ID as the program loading it. This channel signs ad-hoc,
which has no Team ID at all, so macOS refused to let irori load its own Electron
framework and stopped the process before it could draw a window.

The hardened runtime is only meaningful alongside notarization, which this
channel does not have, so it is now off. The bundle is still signed and sealed,
so Gatekeeper still gives the recoverable unverified-developer dialog rather than
refusing the application as damaged.

It returns with Developer ID signing, where a single real Team ID covers every
component, and that change will need its own check on a real Mac.

## Why the earlier build passed its tests

The Mac package job launched the signed package, drove the terminal and the
bundled rclone, and passed — on a macOS 15 runner, while the build is published
for macOS 26. That operating system did not enforce what macOS 26 enforces, so
the job was not evidence about the machine the download was for. The Mac package
job now runs on macOS 26, and the signature check now requires the hardened
runtime flag to be absent rather than present.

## Installing

Download `irori-0.1.5-macos-arm64.dmg`, open it, and drag **irori** into
**アプリケーション**. This build is for Apple silicon; Intel Macs are not
published.

The first launch is still refused, because the package carries no distribution
signature. Open **システム設定 → プライバシーとセキュリティ**, find irori's blocked
notice under セキュリティ, and press **このまま開く**. The button appears only just
after an attempt to open the app, so if it is missing, try opening irori again
and return to that pane. Later launches behave normally.

On macOS 26, the package job verifies the bundle Forge produced and the copy
inside the disk image: the `_CodeSignature` seal exists, `codesign --verify
--deep --strict` passes over the app, its helpers and its frameworks, the
identifier is `io.github.deltaiseiozaki.irori`, the signature is ad-hoc, and the
hardened runtime flag is absent. Gatekeeper's own verdict is recorded rather than
asserted, because `spctl` rejects unnotarized code by design. That job then
launches the signed package from a different path and exercises SDK imports,
save/undo/redo, native clipboard image paste, the CSV graph, Japanese note and
terminal file saves, private drafts, recoverable note deletion after restart,
single-instance ownership and bundled rclone.

## Remaining boundaries

Passing CI is not acceptance on an installed Mac. Installation, the approval
step, Japanese input, real CLI accounts, Git operations and Google connections
still need a device trial. Please report the displayed version and the exact
steps.

Google connections remain read-only. On a Mac they use macOS's own NFS mount and
need no extra installation, but no real mount has been observed on a device.
Drive uploads, real OpenCode and Pi model turns, notarized signing, Intel Mac
packaging and cross-device history remain separate work.

Read [the distribution notes](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/DISTRIBUTION.md)
and [the full release plan](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/RELEASE-PLAN.md).
Report the displayed version, OS and exact error through
[GitHub Issues](https://github.com/DeL-TaiseiOzaki/irori/issues), omitting private
notes, credentials and OAuth URLs. Source is MIT licensed; dependencies retain
their upstream terms.
