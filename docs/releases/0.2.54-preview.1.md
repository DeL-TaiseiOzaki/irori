# irori 0.2.54 preview 1 — what the screen says is what agents get

- Conversations start in standard access. Full access is your choice for a
  conversation; while a run is in full access its log says so, and the access
  can no longer be changed under a running turn. A send from the Overview shows
  the access it uses.
- A connection marked read-only is now read-only for Claude Code and Codex in
  standard access too, and every CLI is told which connected folders are
  read-only. The connection screen says what read-only does and does not cover.
- A hand-off from the irori agent runs in the vault agent's standard access,
  never in the irori agent's mode.
- Before an agent runs with configuration that acts without asking — Claude
  Code project settings and `.mcp.json`, OpenCode's project config and plugins,
  Pi's extensions, a connected folder's `.claude`, the shared Schema's hooks —
  irori lists it and asks you, and asks again when it changes. The `/` command
  list leaves a folder's own settings out until you allow them.
- Git asks before it runs in a repository whose own configuration runs
  programs (hooks, filters, diff and merge drivers, credential and SSH helpers).
- When an agent uses `irori connect`, `irori work`, `irori add`,
  `irori remove` or `irori run`, irori asks you each time.
- A link to a program, script or shortcut no longer starts it: irori offers to
  show it in its folder.
- On Windows, irori finds the programs it starts on the search path only, never
  in the folder they work in.
- Requests to approve say when part of them is too long to show; a Codex
  access request says it lasts until the request ends; an MCP server's form
  names the server.
- Routines: the review reads every file each time, and each program step runs
  only while the folder still holds what you reviewed. More environment names
  are refused as secret names, and encoded forms of a secret are hidden in run
  records as well.
- Saving the environment leaves credential files (`.env`, keys) on this device,
  and restoring never writes into a Git folder.
- Smaller fixes: a note moved to another vault carries only real image files;
  a terminal answers only the window that opened it; a restored note leaves no
  copy behind; a connected folder's recorded name drops an email address; the
  links in contents stay out of the vault's Git history on this device; a
  document can no longer make the window load files from another computer or
  cover irori with its styles; very long unclosed links and very large sheets no
  longer stall the editor and the viewer.
- What the screens and guides say now matches what happens: deleting in a
  synced folder, removing a vault, deleting a conversation, saving the
  environment, verifying an update, turning the vault agent off, the Schema's
  hooks, and where agents' content goes.
- Electron 44.9.3, zod 4.6.7 and updated dependencies.

## Verification

`npm run build`, `npm test` (new `agent-grants`, `config-approval`,
`git-config-approval` and `environment-files`, with additions to the routine,
keystore, connection, copy, note, session and command tests) and
`npm run test:ui` pass on Linux under Xvfb; `your-ai-ui-smoke` now allows and
checks the confirmation for an agent's `irori add`. The CLIs were exercised
through their protocol fixtures only. Not yet tried on Windows or macOS, where
search-path resolution, `file://` hosts and Claude Code's deny rules for
Windows paths matter most, nor with real CLI accounts.
