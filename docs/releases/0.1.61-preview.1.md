# irori 0.1.61 — recovered indexes and reliable live requests

- A file that was temporarily unreadable returns to search and the generated
  graph on the next successful scan, without requiring a file edit or restart.
- In irori mode and routine steps, a delayed conversation read no longer hides
  a newly arrived permission/question or brings back an answered request.
- Changes in another hibachi no longer reread the whole document open in this one.
- Opening a long conversation holds only its existing display window in memory.
  Tool details are shortened for the view during reading; full stored history
  and the existing 1 MiB tool-detail storage limit are preserved. In a synthetic
  100 MiB history, median heap growth fell from 148 MiB to 21 MiB. This is a
  memory improvement; the measured reading time did not improve.
- Moving or renaming a note on a case-insensitive disk updates differently
  cased body links and frontmatter relations/source references consistently
  with the move preview, including self-links.

## Verification

Regression checks cover delayed live approvals and answers, document-read
counts for another hibachi, temporary filesystem failures, case-insensitive
move references, retained history boundaries and a 64 MiB heap limit. Local
full-suite results and measurement details are in the
[audit](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/AUDIT-2026-09-30.md).

Real provider inference and installed Windows/macOS device acceptance were
not run for this correction. No preview is published until this branch is
merged and the native release jobs succeed. An installed 0.1.29 or later can
receive the published version through **更新して再起動**.
