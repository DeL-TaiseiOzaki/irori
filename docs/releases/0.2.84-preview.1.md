# irori 0.2.84 preview 1 — Shared skills are every CLI's own skills

- **Shared Schema skills on Codex, OpenCode and the Antigravity CLI.** A skill
  in the Shared Schema was a skill of Claude Code and Pi, but Codex, OpenCode
  and the Antigravity CLI only heard it listed in the request. Each of them now
  gets the shared skills as skills of its own, as it gets a vault's own: Codex
  can take one as a `$name` or `/name` skill and offers them by itself, as do
  OpenCode and the Antigravity CLI. A vault's or the irori agent's skill of the
  same name is still used instead. Nothing is written into a vault: irori gives
  each run a folder in its own data, removed when the run ends. OpenCode and the
  Antigravity CLI get copies, so a run cannot change the Shared Schema's skills
  through them. Hermes Agent still hears the shared skills listed, as it does a
  vault's.
- **The guide says where the Shared Schema does not reach yet:** the agent of a
  vault on an SSH host.

## Verification

`npm run build` and `npm test` pass on Linux.

- A new stand-in test runs a vault agent on Codex, OpenCode and the Antigravity
  CLI with four shared skills, two of which the vault also has (one of them
  malformed) and one of which is in the vault's `.claude/skills`. Codex gets the
  others as an extra skill root before its thread starts and again before it
  resumes; OpenCode finds copies in a skill path added after the person's own,
  at the same place on each run; the Antigravity CLI finds copies in an added
  workspace folder. The vault's own skills are not replaced, and nothing is left
  after the runs. Without the change, or without any one of the fixes from an
  independent review, the test fails.
- The stand-ins follow Codex 0.170.0's and OpenCode 1.19.6's source and the
  Antigravity CLI's documentation. No real Codex, OpenCode or Antigravity CLI
  was run.

Not tried on macOS or Windows.
