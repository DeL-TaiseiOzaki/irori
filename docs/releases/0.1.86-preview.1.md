# irori 0.1.86 preview 1 — Folder indexes generated with the graph

In a knowledge base made from the recommended template (an Open Knowledge
Format bundle with `.property/property.json`), **索引を更新** in the ontology
view now writes every folder's `index.md` along with the graph index. Each
index lists the folder's subfolders, then its pages under their type's heading,
one line each with the page's description. A folder's description is kept;
other text written into an index is not. The same pages give the same files on
every device, and the panel says how many indexes an update would add or change.
A knowledge base that declares its graph in `.irori/ontology.json` keeps its
tables and gets its folder indexes all the same.

Also in this release:

- The `README.md` at the top of a hibachi is part of Schema, like `AGENTS.md`.
  It no longer opens with a properties block, and search leaves it out.
- A link to a folder, such as `wiki/`, opens that folder's `index.md`.
- Pulling a change to `.irori/scope.json` from another device is accepted when
  it keeps the hibachi's identity: renamed Knowledge and Contents folders,
  layer names and the look apply at once, without a restart. A change to the
  identity, a removed file or an invalid folder name is still refused.

## Verification

`npm run build`, `npm test` and the Electron UI suites pass. Unit tests build
a disposable bundle with nested folders, decomposed Japanese names, undeclared
and missing types, missing descriptions, kept folder descriptions and root
frontmatter, check that a second update writes nothing and that every generated
link resolves, and pull accepted and refused declarations through a local
remote. Not tried with Windows, macOS or a real knowledge base.
