# irori 0.1.20 — Windows and Mac preview, authorship that travels with Git

Since 0.1.12 irori has recorded which lines of a note an agent wrote, but only
on the device that saw it happen. This preview writes that record into the
knowledge base's Git history in the Git AI Standard format, so it reaches your
other devices, your collaborators and tools such as git-ai. An installed 0.1.19
or earlier on either platform is offered this by **更新を確認**.

## What changed

**A commit carries who wrote its lines.** When you commit through irori's Git
panel, irori attaches an authorship note (`refs/notes/ai`) naming the lines an
agent wrote in the committed notes. Your own lines are never claimed for anyone,
and a commit with no agent line gets no note. Nothing is added to the files of
the knowledge base.

**irori reads notes whoever wrote them.** When a note you open has authorship
notes in its history — written by irori on another device, by a collaborator
or by git-ai — the line above the note counts those lines too and says that
part of the count comes from the repository's notes. Source view marks them,
and an agent asked about the note is told who wrote which lines.

**Notes follow Fetch, Pull and Push.** Fetch and Pull bring the remote's notes
and merge them with yours; Push sends yours after the branch and never
overwrites someone else's. If the remote has notes you have not fetched yet,
Push says so and Fetch settles it. The Push confirmation mentions that the
notes go too.

**git-ai reads what irori writes.** `git-ai blame` shows the agent's lines as
the agent's, and `git-ai stats` counts them as AI additions.

## Installing

**Windows 11 x64:** download `irori-0.1.20-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.20-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests use disposable Git repositories: a note
written by irori and read back on a device with no record of its own, a note in
the standard's own layout, a note another tool already attached kept intact,
Fetch and Push against a remote and a second clone with diverged notes, and a
crafted note read in linear time. An Electron suite commits through the Git
panel, reads a seeded note and sees the notes reach the remote on Push. The
git-ai command-line tool 1.7.5 read a note irori wrote.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

irori does not know which model an agent used, so the note says "unknown". Your
own lines are left unclaimed rather than marked as yours. A merge commit gets no
note. GitHub's "Squash and merge" and "Rebase and merge" create new commits
without notes, so authorship recorded on a branch merged that way does not
reach `main`. Only the fifty newest noted commits of a file are read. Google
connections remain read-only. Drive uploads, real OpenCode and Pi model turns,
Developer ID signing with notarization, and cross-device history remain separate
work.
