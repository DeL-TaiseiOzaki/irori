# irori 0.1.20 — Windows and Mac preview, the lines that are yours

A note written together with an agent needs one thing kept clear: which lines are
yours. They are what an agent has to understand to work with you. This preview
records them, shows them, and tells an agent about them when it matters. An
installed 0.1.19 or earlier on either platform is offered this by **更新を確認**.

## What changed

**irori marks the lines you wrote or revised.** A line counts as yours when you
typed it or changed any part of it: changing part of a sentence is how you make
it say what you mean. Above the note, irori says how many lines are yours, and
source view marks each one at its left edge. What an agent wrote, and what
arrived by pull or from another editor, carries no mark.

**Only what you changed is yours.** When you save, irori compares the note with
what was on disk and marks only the lines you introduced. Earlier previews
claimed every line irori had not seen before the first time you saved, including
lines that came in by pull; marks recorded by those previews are not carried
over.

**Claude Code hears about your lines before it changes them.** When Claude Code
is about to edit a file in a way that changes one of your lines, irori tells it
which lines, quoted, as information and not as an instruction. An edit that
leaves your lines alone adds nothing.

**Any agent can be told when you want it to.** With a note open that has your
lines, the request box offers **自分の行を伝える**. Tick it and the request names
those lines; it is off by default, because an agent does not need it for every
request.

The 0.1.12 display of how many lines each agent wrote is replaced by this.

## Installing

**Windows 11 x64:** download `irori-0.1.20-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.20-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests cover a save that marks only what it introduced,
a revised agent line becoming yours, marks that survive moves and reflow,
records from earlier previews not being read, how each file tool's edit is
applied, the notice naming exactly the lines an edit would change, and the
request naming your lines only when asked. An Electron suite checks that an
agent's appended line is not counted, that a line you type and save is, that the
count survives a restart, and that 自分の行を伝える starts unticked.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac. The notice to Claude Code was checked against
irori's own logic, not observed in a real Claude Code session.

Only Claude Code is told at edit time; Codex, OpenCode and Pi are told through
the tickbox. Which words inside a line are yours is not kept — the line is. Text
you paste counts as yours. The record stays on this device and does not reach a
collaborator. Google connections remain read-only. Drive uploads, real OpenCode
and Pi model turns, Developer ID signing with notarization, and cross-device
history remain separate work.
