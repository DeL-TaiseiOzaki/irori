# irori 0.2.65 preview 1 — find in the file on show

- **Ctrl+F** (**⌘F** on a Mac), or **ファイル内を検索** (Find in file) in the
  file's **…** menu, opens a find bar above the file on show. It finds words in
  a note in the rich view (across bold and links, and inside code blocks), code
  and other text in the source view, a CSV table, a PDF, a Word document, a
  PowerPoint deck and a spreadsheet. Images have no text to find, and their menu
  does not offer it.
- The bar counts every occurrence in the file, not only what is drawn: a CSV
  table and a spreadsheet turn to the page of the one shown, a spreadsheet
  searches every sheet and opens the sheet of the one shown, and a PDF scrolls
  to its page and marks it once the page is drawn.
- Case and full-width ASCII do not matter. Enter or F3 goes to the next
  occurrence, Shift+Enter to the previous one, and Esc closes the bar. In a
  note, closing it selects the occurrence it was on; words selected in the file
  when the bar opens are what it looks for. An edit while the bar is open is
  counted again.
- The bar sits above the file's scrolling view, so it covers neither the file
  nor a viewer's zoom, paging or sheet tabs. In the source view it takes the
  place of CodeMirror's own search panel; the terminal keeps Ctrl+F for the
  shell.

## Verification

`npm run build`, `npm run format:check`, `npm test` and `npm run test:ui` pass
on Linux under Xvfb. The new `find-in-file` test covers how text is folded; the
new `find-in-file-ui-smoke` opens the bar from the menu and with Ctrl+F over a
rich note (a word across bold, one in a code block, selected on Esc, recounted
after an edit), a Python file without CodeMirror's panel, a CSV table past its
first page, a PDF, Word, slides and both sheets of a workbook, and an image. Not
seen on Windows or macOS.
