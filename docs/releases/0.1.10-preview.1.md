# irori 0.1.10 — Windows and Mac preview, one agent per knowledge base

Until now a single run locked the whole workspace: while an agent worked in one
knowledge base, no other space could start one, and the space could not even be
changed. A workspace joins several independent repositories, so that limit
contradicted the thing the product is for. This preview lifts it. An installed
0.1.9 or earlier on either platform is offered it by **更新を確認**.

## What changed

**Each knowledge base runs its own agent.** Two spaces can work at the same
time, each with its own CLI, its own conversation and its own stop button. The
spaces are separate checkouts, so their runs never write the same bytes.

**One agent per space, still.** Starting a second agent in a space that is
already running one is refused, as before. That is the boundary that protects a
knowledge base from two writers.

**A stop stops one run.** Cancelling a space's run leaves every other space
running. Each space's permission and question prompts now belong to that space's
run, so answering or cancelling in one no longer discards the other's pending
requests.

**Switching spaces while an agent works.** The explorer no longer refuses a
different space during a run. Sending is still held while instructions are
queued, because a queue is processed for the space being shown.

**Operations that touch one space wait for that space only.** Organising notes,
restoring a deleted note and changing a space's cloud connection now check that
space's run. Registering a new space, removing an account and cloning still wait
for every run to finish, because they change the workspace itself.

## Installing

**Windows 11 x64:** download `irori-0.1.10-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.10-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership and bundled rclone. On macOS 26 it first
verifies the bundle and the copy inside the disk image. Tests use disposable data
and do not run a real model turn.

A behaviour test starts runs in two registered spaces, asserts both are running,
asserts a second agent in one of them is refused, and cancels them one at a time
to check that the first cancellation leaves the other running and that each run
reports its own outcome. No provider is launched.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Two real CLI processes running at once have not been exercised against live
provider accounts; the behaviour test cancels before either run reaches a
provider launch. Memory and CPU under two simultaneous native agents are not
measured. The conversation panel still shows one space at a time, and queued
instructions are only processed for the space on screen, so a queue left behind
in another space waits until that space is selected again. Google connections
remain read-only. Drive uploads, real OpenCode and Pi model turns, Developer ID
signing with notarization, and cross-device history remain separate work.
