# irori 0.2.78 preview 1 — Passwords and verification codes for SSH hosts, typed in irori

- What `ssh` asks while it connects to an SSH host is now asked in irori's
  window, in a dialog named **（ホスト名）に接続**: a password, a key's
  passphrase, a verification code of two-step sign-in, and whether to trust the
  key of a host seen for the first time. Until now such a host could not be
  connected to unless `ssh` reached it without asking.
- What you type is hidden unless **入力を表示** is checked. It is handed to
  `ssh` and kept nowhere by irori.
- A host's key is shown with its fingerprint, in ssh's own words; **続ける**
  lets `ssh` remember it.
- After a wrong answer `ssh` asks the same again, and the dialog says so.
- **キャンセル** ends that connection. irori then asks nothing by itself: only
  **接続**, or **再試行** where a folder is chosen, asks again.
- Through a jump host (`ProxyJump` in your ssh configuration), the jump host
  and the destination each ask.
- A connection is one login, also the first one, which installs irori's files
  on the host, and one after an update of irori. A verification code is typed
  once. Before, a first connection signed in four times.
- When irori reconnects by itself to collect a hand-off's report, it asks
  nothing. A host that needs an answer stays unconnected until **接続**.
- On Windows the program `ssh` runs to ask, `irori-askpass.exe`, ships with the
  application.

## Verification

On Linux, with the system's `ssh` (OpenSSH 9.6):

- Against a real `sshd` that asks for a password and a time-based verification
  code, through the window: a host's key, a wrong password, the password and
  the code, then connected. `sshd` saw one connection.
- A key with a passphrase, and a jump host where each hop asks, from the
  command line with the same program.
- `npm test` signs in to a stand-in server that asks for a password and a code
  (`tests/fixtures/ssh-server.ts`); `npm run test:ui` covers the dialog.

On Windows and macOS nothing was tried by hand. CI's packaged-app smoke runs
the packaged application against the stand-in server on each system it
packages for, which is where `irori-askpass.exe` and the system's `ssh.exe`
are run. A key that needs a touch (FIDO) was not tried anywhere.
