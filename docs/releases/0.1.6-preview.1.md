# irori 0.1.6 — Windows and Mac preview, knowledge base skills

This preview brings both downloads up to date with irori's `main`. Windows was
at 0.1.5 preview.2 and the Mac at 0.1.5 preview.3; both now carry the same
0.1.6 application. An installed 0.1.5 on either platform is offered this update
by **更新を確認**, because the application version itself advanced.

## What changed

**Skills declared by a knowledge base.** A KB can keep its own procedures in
`.agents/skills/<name>/SKILL.md`. When the selected KB declares at least one, a
skill selector appears beside the agent selector in the composer, defaulting to
なし. The chosen skill's instructions are sent ahead of your request to whichever
of Codex, Claude Code, OpenCode or Pi is running, and the conversation records
which skill ran. irori reads that directory and never writes into it. A package
that cannot be read is named under the composer instead of disappearing, and a
run naming a skill the KB does not declare fails rather than running without it.

**Tool folders stay out of the knowledge pane.** A top-level entry whose name
begins with a dot is now treated as configuration. A KB that is also an Obsidian
vault or a Git checkout, or is used with another agent tool, no longer shows
`.obsidian/`, `.github/`, `.gitignore` or `.claudian/` among your notes. They
appear in the schema pane instead, beside the agent folders such as `.claude/`
that were already there. Search already skipped them.

**Third-party notice.** The bundled notice now names the VS Code extension by its
new repository name, irori-extention.

The Mac launch fix from 0.1.5 preview.3 is included. Nothing else about
installation changed.

## Installing

**Windows 11 x64:** download `irori-0.1.6-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.6-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

Each package job launches the packaged application from a different path. It
exercises SDK imports, save/undo/redo, native clipboard image paste, the CSV
graph, Japanese note and terminal file saves, private drafts, recoverable note
deletion after restart, single-instance ownership and bundled rclone. On macOS 26
it first verifies the bundle and the copy inside the disk image: the signature
seal exists, `codesign --verify --deep --strict` passes, the signature is ad-hoc
and the hardened runtime flag is absent. Tests use disposable data and do not run
a real model turn.

Separately, before this release, a real Claude Code turn on a Linux development
machine used a copy of the irori-templete knowledge base with its `journal` skill
selected. The skill reached Claude Code, and the only change in the KB was the
new journal entry. That run was not on an installed build.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Skills are chosen per turn from a flat list, with no search and no per-skill
argument, and an agent is not offered them to invoke on its own. Google
connections remain read-only. Drive uploads, real OpenCode and Pi model turns,
Developer ID signing with notarization, and cross-device history remain separate
work.
