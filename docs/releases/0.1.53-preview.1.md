# irori 0.1.53 — make a hibachi here and publish it to GitHub

Until now a hibachi started as a repository on GitHub and was cloned into irori.
Now it can also start in irori and become a GitHub repository.

## A new hibachi

- **hibachi を追加 → 新しく作成** asks for a parent folder, a new folder name and
  the hibachi's name. irori makes the folder, starts it as a Git repository on
  `main`, registers it, and makes a first commit that holds only
  `.irori/scope.json` and a `.gitignore` leaving `contents` out.
- Tick **GitHub にもリポジトリを作成する** to publish it in the same step: pick the
  account or organization, the repository name and whether it is private
  (the default) or public.
- If the first commit or publishing fails (no Git author name, a hook, a name
  already taken on GitHub), the hibachi is still created; the form says why and
  offers **開く**.

## Publishing an existing hibachi

- A hibachi that is an ordinary folder shows **Git を始める** in its 変更 view.
  It starts Git on `main` and keeps every file as it is.
- A hibachi with commits and no remote shows **GitHub に公開…**. It creates the
  repository on GitHub, sets it as `origin` and sends the current branch and the
  authorship notes, exactly as **Push** does.

This uses the GitHub CLI (`gh`): install it and sign in with `gh auth login`.
irori never reads the token. Organizations appear when gh's sign-in can list
them (the `read:org` scope); otherwise only your own account is offered.

## Installing

**Windows 11 x64:** download `irori-0.1.53-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.53-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. Later launches behave normally. Keep
irori in **アプリケーション**: the in-app update replaces the app where it is.

An installed 0.1.29 or later offers this version with **更新して再起動**.

## Verification

- The full build, unit tests (including real Git repositories and a stand-in
  `gh`) and the Electron Git journey passed: a hibachi created, refused by
  GitHub for an existing name, then published from Source control, and an
  ordinary folder started in Git, committed and published to an organization.

## Remaining boundaries

- Not yet checked against a real GitHub account: the `gh repo create` call,
  `gh config get git_protocol`, and listing organizations without `read:org`.
- The new hibachi is empty apart from its registration; it does not copy the
  irori-templete structure.
