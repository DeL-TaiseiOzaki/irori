# irori 0.1.72 — routines can use your tokens

- A routine step that needs a token or API key, such as for Slack or Teams,
  names it under `secrets:`. Its row asks for it with **<NAME> を入力**. The
  value is kept on this device, sealed with the key your OS keeps, and is
  never shown again.
- Only the `run` steps that name a secret receive it, as an environment
  variable. Agent steps never do. Wherever a value would appear in a run's
  record, `***` shows instead.
- Tokens that expire and are refreshed keep working: a step writes the new
  values to the file `IRORI_SECRETS_OUT` names, and later runs use them.
- Stored names are listed under **シークレット** in the routines view, to
  replace or delete. On Linux without a keyring, irori does not store secrets
  and says so.

## Verification

Unit tests cover the keychain check (Linux `basic_text` is refused), the store,
hiding values in output that arrives in pieces, giving values only to the
steps that name them, and write-back, including refused and unfinished lines.
The routines Electron UI suite enters a secret from a row, sees it in the
review, finds the output hidden, writes a new value back and deletes it.
That suite used a stand-in store, since the test display has no keychain.
Real macOS Keychain, Windows DPAPI and a Linux secret service were not tried.
