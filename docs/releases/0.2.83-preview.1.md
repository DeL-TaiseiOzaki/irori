# irori 0.2.83 preview 1 — Vaults on SSH hosts in their own box on the mapping

- **irori mode's mapping** shows where each vault is. A vault on an SSH host
  was drawn among this computer's vaults, with nothing to tell it was on
  another machine. This computer's vaults now come first, and each SSH host's
  vaults stand below them in a box named after the host, one box per host.
  The irori agent's hand-off lines and the reference lines reach into the box
  as before, and a screen reader reads the host's name with the vault's.
- **The view is called マッピング** (*Mapping* in English). It was **地図**
  (*Map*). The vault settings' preview and the user guide use the new name.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass on Linux under Xvfb.

- `tests/overview.test.ts` checks that each host's vaults are inside its own
  box in the workspace's order, that this computer's vaults are in none, that
  the boxes do not overlap and leave room for the host's name, and that 24
  vaults on four hosts still fit the board.
- The SSH hosts smoke opens irori mode after adding a vault on a stand-in host
  and expects that vault, with its name and state, inside a box named
  **Lab server**, and this computer's vault outside it.

Not tried on macOS or Windows, or against a real SSH host.
