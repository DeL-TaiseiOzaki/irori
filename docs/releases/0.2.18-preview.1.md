# irori 0.2.18 preview 1 — make a routine from a form, and set its secrets in one place

- **新しいルーティン** opens a form instead of a name dialog and a blank
  `routine.yaml`: the name, the place, and the steps. An agent step has its
  prompt, the vaults handed to the irori agent, the access, the CLI and a
  model; a program step is a command written as in a terminal or a file of the
  routine's folder. Steps are added, moved and deleted. **YAML** switches to
  the text itself.
- The editor says what still stops the routine as you write it, the same
  reason its row would show. Saving from the form keeps the comments of the
  steps you kept; text the form cannot show opens as YAML with the reason.
- A program step's secrets are chips in the editor: stored ones are checked,
  and a missing one has **値を入力** right there.
- The page's header has **シークレット**: the stored names with the routines
  that use them, the ones routines still need, and **追加** for a new name and
  its value before any routine names it. Values are still never shown again.
- The editor opens the routine's folder in the system's file manager, where a
  program step's file goes.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/routines.test.ts` covers reading `routine.yaml` as the form and writing
it back (unchanged text, kept comments, moved and new steps, a vault's agent,
text the form cannot show, an unfinished step, command lines), a new routine
given its text and the folder's files for the editor. `routines-ui-smoke`
makes a routine from the form, edits it as YAML and as a form, opens unfit text
as YAML, and enters and adds secrets from the editor and the シークレット sheet,
with the reversible test store. The macOS Keychain and Windows DPAPI were not
tried, and no real CLI was run.
