# irori 0.2.63 preview 1 — a window that shows the work

The window now shows what a note and a conversation need. How a conversation
runs is set from its column in one menu, and what only a developer's way of
working uses is in the settings, joining the window when turned on there
([ADR 059](../decisions/059-the-window-shows-the-work.md)).

## The agent's column

- **One menu for how a conversation runs.** The access, the model and the
  thinking level were three selects under the instruction box. They are now one
  button at its foot, which names the model and level in use and opens a menu
  in three parts: モデル, 思考量 and アクセス. The menu stays open while several
  are chosen. A conversation in full access says so on the button, in the
  attention colour.
- **The instruction box is a card.** It floats over the conversation and is
  ringed in the focus colour while it is written in. What the request is about
  shows as round chips; the send button is round, and an outline until there is
  something to send.
- **An empty conversation says who the agent is**, in one sentence, with the
  two keys worth knowing: `/` for commands and Enter to send.
- Menus across irori let the window show faintly through them.
- The conversation's **会話と接続** menu is gone. Each CLI's version, or that it
  was not found, is under **エージェント → 共通 → この端末の CLI**.
- The skill reach check (到達確認) is on a vault's home under Schema only, no
  longer under the instruction box too.

## What the window shows

- **表示 → 画面に出すもの** (Display → What the window shows) lists each
  optional item with a switch, where it appears and what holds while it is off.
  **すべて出す** (Show all) puts every item on at once; **既定に戻す** (Back to
  default) returns to the list below.
- **On the window from the start:** the access and the model with its thinking
  level (the two parts of the conversation's menu), and the skill of a request
  for a vault that has skills. Each can be turned off.
- **Off the window after this update, until turned on:**
  - under the instruction box: whether to tell the agent which lines a person
    wrote;
  - at the top of a conversation: the buttons that add a column and hide the
    page;
  - along the window's foot: the Git branch, the terminal's button (also on a
    vault's home) and irori's version.
- Taking a control off the window does not change what it was set to: a
  conversation keeps its access and its model. A skill and the person's lines
  are not sent while their control is off.
- What is in use stays in view: full access on the conversation's button, the
  terminal's button while a terminal is open (Ctrl+` still opens and closes
  it), and the button that shows the page while it is hidden.
- These choices are kept on the device and are part of the environment saved
  to GitHub.

## Verification

`npm run build`, `npm run format:check`, `npm test` and `npm run test:ui` pass.
The new `window-items-ui-smoke` opens a new device's window, checks the
conversation's menu and that none of the items above is on the window, takes
each part of the menu off and puts it back, turns the terminal on and off from
the settings, shows all and returns to the default, and checks that full access
and an open terminal stay in view. `harness-ui-smoke` chooses a model, a
thinking level and an access through the menu for Pi, OpenCode, Hermes Agent
and the Antigravity CLI, and types a model name where the CLI lists none. Screens
were inspected on Linux under Xvfb in Japanese (hearth) and English (light),
with and without the vault agent. Not seen on Windows or macOS.
