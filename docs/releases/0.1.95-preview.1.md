# irori 0.1.95 preview 1 — Agents use what irori does, and a header that fits

The irori agent and every hibachi agent can now do through irori what you do
in irori. A hibachi agent has the `irori` command for its own hibachi:

- `irori move` moves or renames a note, and the links into it, its comments and
  its images follow, as when you move it in the explorer.
- `irori trash` puts a note in irori's trash.
- `irori comment` and `irori resolve` leave comments for you and remove them.
  Comments are signed with the agent's name.
- `irori index` updates the indexes.
- `irori set`, `irori layer` and `irori connect` change the hibachi as its
  settings do, including its color and icon.

Registering, grouping and removing hibachis and starting routines stay with
the irori agent. Secrets, a routine's first review, accounts and updates stay
with you. Decided in ADR 031.

irori mode's header stays on one line in a narrow window. The hibachi count
goes first, then the map/columns switch, search and add buttons show their
icons only. The words used to wrap letter by letter and overflow their frames.

## Verification

`npm run build`, `npm test` and the Electron UI suites pass.

- The command test runs a hibachi agent's command and checks that:
  - the irori agent's forms and another hibachi are refused;
  - the hibachi's color and icon change;
  - a note moves into a folder;
  - a comment is signed by the agent and resolved by its id;
  - the index updates.
- A Pi protocol fixture shows a hibachi agent run receiving the command and its
  preamble.
- The overview smoke shrinks the window and checks that the header neither
  wraps nor overflows.

Not tried with a real CLI, Windows or macOS.
