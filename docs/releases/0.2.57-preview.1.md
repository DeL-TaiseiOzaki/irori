# irori 0.2.57 preview 1 — each conversation keeps its access

- The access chosen in the composer (standard or full access) now belongs to
  the conversation, for vault agents and the irori agent alike. Once changed,
  every later instruction in that conversation keeps it, after a restart too,
  until you change it again.
- Until now the choice belonged to the panel's column: a new conversation
  there started in the previous one's full access, and choosing standard in it
  turned the first conversation back to standard once it was shown again,
  which also started its CLI session over. Neither happens now: a new
  conversation starts in standard access, and no conversation takes another's.
- A send from the Overview keeps the conversation's own access instead of
  always the standard one, and its footer names that access.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass, with a new test of the
access each conversation keeps across a restart, and the irori mode threads
smoke checking, in the irori agent's column and in a vault's, that full access
stays through later sends, a new conversation starts standard, and the first
conversation returns to full access with its session going on. Protocol
fixtures only; not yet tried with a real CLI turn.
