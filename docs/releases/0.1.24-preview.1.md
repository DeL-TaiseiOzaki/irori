# irori 0.1.24 — Windows and Mac preview, a graph index the knowledge base carries

A knowledge base written as an Open Knowledge Format bundle — pages under
`Knowledge_Base/` with `type`, `title` and `relations` in their frontmatter — can
now show its graph without anyone maintaining a CSV pair by hand. irori generates
the index from the pages, the knowledge base carries it in Git, and every device
shows the same graph for the same commit. An installed 0.1.23 or earlier on
either platform is offered this by **更新を確認**.

## What changed

**The graph comes from the pages.** With a KB open, **オントロジー** in a
knowledge base that declares no `.irori/ontology.json` offers **グラフ索引を作成**.
irori walks the pages of `Knowledge_Base/`, reads each page's frontmatter, and
writes `Knowledge_Base/ontology/entities.csv` (one row per page that takes part
in a relation: its path inside the bundle as the id, its title as the label, its
path as the note and its type as the group), `relations.csv` (one row per
relation) and a short `index.md` saying the files are generated. The graph then
opens from those tables as any declared CSV pair does, with the same filters,
the same entity list and the same note links.

**The same pages give the same bytes on any device.** Paths are normalised,
rows are sorted, line ends and quoting are fixed, so a regenerated index differs
only when the graph does. Commit `Knowledge_Base/ontology/` through the ordinary
Git flow and another device shows the same graph from the same commit.

**irori tells you when the index is behind the pages.** With a generated index,
the panel says whether it still matches the pages, and if not, how many entity
rows and relation rows an update would add and remove; **グラフ索引を更新**
rewrites only the files whose bytes change. Editing a page's body does not make
the index stale; only what the graph is made of does. Relations irori leaves
out — a URL such as `same_as`, a page that does not exist, a folder's
`index.md`, a path outside the bundle — are counted and shown.

**A declared CSV pair still wins.** A knowledge base with `.irori/ontology.json`
behaves exactly as before: irori reads the declared files and never generates
over them.

## Installing

**Windows 11 x64:** download `irori-0.1.24-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.24-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests generate the index from a disposable bundle and
check the exact bytes, their independence from the order pages are met in, the
handling of decomposed file names, every exclusion and its count, a title with a
comma read back through the graph reader, duplicate relations collapsing, the
refusal above the graph reader's limits, and the freshness report before and
after a page's relations change. The Electron UI journey generates the index from
a bundle, sees the graph, changes a page on disk, reads the stale counts and
updates.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

The index covers pages under `Knowledge_Base/`; a note kept elsewhere in the
knowledge layer is not part of the graph. Ordinary links in a page's body are not
relations; only the `relations` list in its frontmatter is. The index is
generated on request, not on every save. Google connections remain read-only.
Drive uploads, real OpenCode and Pi model turns, Developer ID signing with
notarization, and cross-device history remain separate work.
