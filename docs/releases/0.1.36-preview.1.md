# irori 0.1.36 — Rename, move, delete and paste images in Drive folders, and see why an upload stalls

This version finishes editing Google Drive folders from irori.

- **Rename, move and delete.** In an editable Drive folder, use the **…** menu
  beside a file or folder in the sidebar, or the buttons above an open Drive
  file. Renaming and moving keep the file itself in Drive, with its version
  history and sharing. Deleting sends it to Google Drive's trash, where it can be
  restored for 30 days. The connected folder itself is still renamed or removed
  in the connection dialog.
- **Images in Drive notes.** Paste or drop an image into a note in an editable
  Drive folder; it is saved beside the note under `_assets`, as in a KB.
- **Changes made elsewhere are not overwritten.** Before saving a Drive file,
  irori asks Google Drive whether the file changed since you opened it, for
  example on another computer. If it did, the save is refused as a conflict, your
  text is kept as a draft, and the Drive version is shown so you can combine
  them. An open Drive file is also checked every 25 seconds. When Drive cannot
  be reached, saving goes ahead as before and uploads once it can.
- **Why an upload stalls.** When saved changes cannot reach Google Drive, the
  connection dialog now says why: no permission to write to the folder (for
  example, shared with you view-only), Drive storage full, the sign-in needs
  renewing, no connection, or Google limiting requests.
- **Stuck changes no longer lock the folder.** If changes cannot be sent,
  **接続を解除** and **読み取り専用にする** offer to go ahead without waiting.
  The changes stay on this device and are uploaded the next time the folder is
  connected as editable.

## Installing

**Windows 11 x64:** download `irori-0.1.36-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.36-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally. Keep irori in **アプリケーション**:
the in-app update replaces the app where it is.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. New tests
cover renaming, moving and deleting (same file kept, destinations and names
checked, the connection folder and read-only folders refused, drafts following
a moved file); images in KB and workspace Drive notes; the Drive version check
(unchanged, changed, our own pending upload, Drive unreachable); upload failure
reasons from rclone's messages and upload queue; and leaving unsent changes
when disconnecting.

## Remaining boundaries

Passing CI is not acceptance on an installed device: these operations on a real
Drive folder still need trials on Windows 11 (WinFsp) and the Mac. A deleted
folder's files go to Drive's trash one by one. Knowledge records that refer to
a moved Drive file keep their old path.
