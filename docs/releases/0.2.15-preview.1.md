# irori 0.2.15 preview 1 — connected folders wait for their drive, and agents get a work folder

- A connected folder whose drive is not ready yet, such as Google Drive for
  desktop starting after irori, shows フォルダを待っています instead of an
  error, and connects by itself once the folder is there. irori looks again
  after a few seconds and then less often (up to every 2 minutes), whenever the
  connections are shown or `irori list` runs, and when the window comes back
  to the front.
- A connected folder that the drive mounted again with a new identity is linked
  again to the folder at the same place. Something else put at
  `contents/<name>` is never replaced; it shows as an error.
- Each vault has a work folder where its agents keep scratch files, results,
  downloads and trial scripts instead of the system's temporary folder. It is
  `.irori/work` in the vault (ignored by Git) unless you choose another folder
  in the vault's settings, under 作業フォルダ, or with `irori work`. The irori
  agent is told each handed vault's work folder and may write there.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/local-folders.test.ts` covers a folder missing at connect time and
linked once it appears, the timer (and its holding off during a run), a folder
that goes away and comes back with a new identity through irori's own link,
something else at `contents/<name>`, and disconnecting while waiting.
`tests/work-folders.test.ts` covers the default folder, choosing and refusing
folders, and a missing chosen folder. `brain-settings-ui-smoke` checks the
作業フォルダ section shows the default and a chosen folder and goes back to the
default. Not tried on Windows with Google Drive for desktop, or with a real
CLI's run.
