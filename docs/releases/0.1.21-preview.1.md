# irori 0.1.21 — Windows and Mac preview, your lines travel with your commits

0.1.20 kept which lines are yours on the device that saw you write them. This
preview writes them into the commits you make in irori, so a second computer, a
collaborator, and git-ai can read them. An installed 0.1.20 or earlier on either
platform is offered this by **更新を確認**.

## What changed

**A commit carries your lines.** When you commit in the ソース管理 panel, irori
attaches a note to the commit naming the lines of each changed note that you
wrote or revised. It uses the Git AI Standard's format under `refs/notes/ai`,
with the key the standard derives from your Git name and email — the same
identity the commit already shows. Nothing an agent wrote is named, and nothing
is added to your files.

**Push and Fetch carry the notes.** Push sends the notes after the branch;
Fetch, Pull and 履歴を統合 bring in the notes others pushed. Notes are never
forced: if the remote has notes this computer has not seen, Push says so, and
the next Fetch merges them.

**Lines in the notes count as a person's.** Open a note on another computer, or
one a collaborator committed, and the lines the notes name are counted and
marked as a person's, wherever they have moved since. The count is now labelled
**人が書いた・直した行**, and the request-box option **人の行を伝える**, since
the lines may be a collaborator's as well as yours. Claude Code's notice before
an edit includes them too.

## Installing

**Windows 11 x64:** download `irori-0.1.21-windows-x64-Setup.exe` and run it. The
installer carries no distribution signature, so Windows shows a warning that the
publisher cannot be verified.

**Mac (Apple silicon):** download `irori-0.1.21-macos-arm64.dmg`, open it, and
drag **irori** into **アプリケーション**. Intel Macs are not supported. The first
launch is refused because the package carries no distribution signature. Open
**システム設定 → プライバシーとセキュリティ**, find irori's blocked notice under
セキュリティ, and press **このまま開く**. The button appears only just after an
attempt to open the app, so if it is missing, open irori again and return to
that pane. Later launches behave normally.

## Verification

The published files are the artifacts of the CI run for the commit named under
**Exact package** below, unchanged except for their download names. Each package
job launches the packaged application from a different path and exercises SDK
imports, save/undo/redo, native clipboard image paste, the CSV graph, Japanese
note and terminal file saves, private drafts, recoverable note deletion after
restart, single-instance ownership, one search and bundled rclone. On macOS 26 it
first verifies the bundle and the copy inside the disk image. Tests use
disposable data and do not run a real model turn.

For this change, behaviour tests cover the note a commit writes (the key, the
lines, the metadata, and no note when only an agent's lines changed), another
computer reading the lines back after they moved, agent and legacy keys being
ignored, a note another tool attached being merged rather than replaced, and
notes travelling through Fetch, Pull and Push with a refused Push and the merge
that follows. An Electron suite checks that a collaborator's line in the notes
is counted, that a commit names the line typed in the app, and that Push carries
the notes.

## Remaining boundaries

Passing CI is not acceptance on an installed device. Installation, Japanese
input, real CLI accounts, Git operations and Google connections still need device
trials on Windows and the Mac.

Only commits made in irori carry your lines. GitHub's squash and rebase merge
buttons make new commits that carry no notes, so use a plain merge where the
lines should reach `main`. A collaborator's lines and yours are counted
together. Codex, OpenCode and Pi still hear about the lines only through the
option in the request box.
