# irori 0.1.98 preview 1 — Hibachis are now vaults

What irori called a hibachi is now a **vault**, and each vault's agent is
called after its vault, such as "Research agent"
([ADR 033](../decisions/033-vaults.md)).

- **One name everywhere.** The app in both languages, the website, the agents'
  instructions and the `irori` command say vault. The map in irori mode is the
  vault map.
- **Nothing to redo.** On first start, irori renames what it wrote before: your
  settings, conversations, routine records, and in the irori agent's folder the
  vault agents' definitions and the standard skills. A routine's
  `routine.yaml` takes the new keys (`vaults:`, `agent: vault`) when irori
  reads it, and a routine you confirmed stays confirmed. An environment saved
  on GitHub by an earlier version restores as before.
- **`irori call` hands work over on Pi and Hermes Agent.** The irori agent
  hands a vault's work to its agent with `irori call <vault> "<task>"`; the
  separate `hibachi` command is gone.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.

- New tests rename a device's records and an irori agent folder written by an
  earlier version, check that a second start changes nothing, read an old
  saved environment, and rewrite old routines while keeping a confirmed one
  confirmed.
- The hand-off tests now run `irori call` through the real launcher and a Pi
  protocol fixture.

Not tried with real Pi or Hermes Agent, or on a device with data from an
earlier version.
