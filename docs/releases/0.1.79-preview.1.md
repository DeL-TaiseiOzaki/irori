# irori 0.1.79 preview 1 — Stays light through long agent sessions

irori no longer slows down the longer a CLI agent works in it.

- A long conversation stays smooth: the log keeps what is on screen when old
  events scroll out, a reply still arriving is redrawn a few times a second
  instead of for every word, and typing in a note no longer redraws the
  agent columns.
- Opening a conversation reads only its newest part, however long its history.
- A file an agent writes refreshes only its own hibachi. Git status, links to a
  note, its authorship and the knowledge history are read once for requests
  that arrive together, at most four Git commands run at a time, and a search
  is no longer cancelled by an agent's writes.
- Tool and cache folders such as `.venv`, `__pycache__` and `.cache` are no
  longer watched.
- **Stop** and quitting end everything an agent started, including commands it
  detached, and give the agent a moment to close its own servers first. If
  irori ends unexpectedly, the agents it started end with it.

## Verification

Unit tests cover reading a conversation from its end (counts of earlier and
damaged lines, CRLF, a reply split across the file and unwritten lines,
recovery after a cut line), coalesced streamed text and its order around a
stop, stopping process trees with checked process identity, coalesced Git
status and authorship, the backlink candidate filter, separate search
cancellation, watcher boundaries, knowledge history caching, stable log keys,
held events joining a snapshot, scope revisions and unchanged polls. The
conversations Electron UI suite keeps an opened step and a message mounted
while a 400-event window slides; the Git suite checks that another hibachi's
file event refreshes nothing in this one. Not measured on a real long session,
and not tried with real CLIs, Windows or macOS.
