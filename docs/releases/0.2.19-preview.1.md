# irori 0.2.19 preview 1 — agents work where you can see, and reply links open the right file

- A path in an agent's reply opens the file it names. A path the irori agent
  writes starts in its own folder, then the workspace's vaults, instead of the
  vault on show; a vault agent's starts in its vault. A bare name such as
  `topic.md` is looked for by name, several matches are each offered, and a file
  that is not there says so instead of opening another.
- `AGENTS.md:12` and other names with a line now open at that line.
- A path to a connected folder's real place opens through the vault it is
  connected in.
- Each workspace can choose the irori agent's folder on its screen (or before
  setting it up), under the folder's path: 開く, フォルダを選ぶ, 既定に戻す. The
  default stays `~/irori/you`. The shared Schema and the irori agent's routines
  stay in the default folder.
- A vault's work folder is now `work` in its contents, where the explorer shows
  it, ignored by Git. What agents left in `.irori/work` moves there.

## Verification

`npm run build`, `npm test` and `npm run test:ui` pass.
`tests/path-links.test.ts` and `tests/agent-folders.test.ts` cover where a path
is looked for, a name found in several vaults, a connected folder's real place,
and choosing and refusing the irori agent's folder. `tests/work-folders.test.ts`
covers `contents/work` and the move from `.irori/work`. `your-ai-ui-smoke`
opens, with Research on show, a Product file and the irori agent's own plan from
its reply, and chooses and resets the workspace's folder; `harness-ui-smoke`
opens `second.md:1` and reports a missing file. Not tried with a real CLI's run
or on Windows.
