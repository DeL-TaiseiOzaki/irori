# irori 0.1.62 — folders on this computer in Contents

- A hibachi's Contents can show a folder on this computer, such as one the
  Google Drive, Dropbox, Box, iCloud or OneDrive app keeps in sync. Choose
  **このコンピューター** in the connection dialog, then **フォルダを選ぶ**. No Google
  sign-in is involved; the service's own app does the syncing.
- While connected the folder appears at `contents/<name>` through a link, so
  CLI agents find it there. In standard access Claude Code and Codex are
  allowed into the folder. Disconnecting removes only the link.
- The folder's path stays on this device. On another computer, choose the same
  folder with **フォルダを選び直す**.
- Files deleted from such a folder in irori go to the system trash.
- Signing in to Google Drive in irori remains for invited testers. The new
  [synced folders guide](https://github.com/DeL-TaiseiOzaki/irori/blob/main/website/docs/content/en/sync-folders.md) explains
  the setup for each service.

## Verification

New tests cover registering, linking, editing, moving and creating notes,
read-only access, overlap and name refusal, replaced links and folders, links
inside the folder, a link left after a crash, binding on another device and
deletion through the trash. The connection dialog was exercised in the Electron
UI suite. Codex 0.159.0's app server reported the folder as a writable root
without running a model.

Real sync apps, installed Windows and macOS builds, Windows junctions and real
Claude Code or Codex turns in the folder were not tested. No preview is
published until this branch is merged and the native release jobs succeed.
