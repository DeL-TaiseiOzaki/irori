# irori 0.1.62 — protected Drive credentials and data-use confirmations

- Google connection stores irori's rclone credential configuration encrypted,
  with a random key protected by the OS secure storage. Existing plaintext
  configuration migrates only after encryption is verified. If secure storage
  is unavailable, Google operations refuse before creating a partial account;
  local notes and runtime diagnostics remain usable.
- First Google use, execution with each native AI CLI, and terminal/routine use
  show a data-use explanation before starting. Denial does not read agent
  materials, create account records or alter live connection settings. Automatic
  reconnection requires a previously recorded Google confirmation.
- Settings can reset these confirmations for the next use. Reset does not stop
  active work, revoke Google authorization or erase retained data.
- Public-site privacy and use/license drafts document current data flows and
  deletion limits. Publisher identity/contact and Google verification remain
  pending; this candidate does not make Google available to everyone by itself.

Credential protection does not encrypt all cached Drive files, notes, source
copies or conversations. First-use confirmations do not approve every tool call
or prove third-party provider compliance. The
[public readiness packet](https://github.com/DeL-TaiseiOzaki/irori/blob/main/docs/GOOGLE-PUBLIC-READINESS.md)
records the remaining gates.

No preview is published until authorized merge and successful native checks.
Real Google consent, native mounts and external model processing are not exercised
by the disposable protocol tests.
