# irori 0.2.86 preview 1 — The Schema checked on real CLIs

- A knowledge folder's own `AGENTS.md` is now named to every CLI, Claude Code
  and Hermes Agent included, to be read before working in that folder. Claude
  Code loads such a file only when it reads a file there, not before writing a
  new one.
- A vault agent's introduction says that a knowledge folder's `AGENTS.md` is
  that folder's instructions, not material.
- Claude Code no longer gets the vault's `AGENTS.md` a second time on every
  request, and the panel no longer says each time that Claude Code did not load
  it. irori now knows from the session's start whether Claude Code loaded it
  ([ADR 058](../decisions/058-every-schema-setting-reaches-every-cli.md), revised).

## Verification

`npm run build` and `npm test` pass. `tests/schema-reach.test.ts` now speaks
as Claude Code 2.1.316 does, and its Claude Code case fails without the change.
A new real-CLI acceptance, `npm run test:schema-reach`, ran Claude Code 2.1.316,
Codex 0.166.0 and the Antigravity CLI 1.5.12 in a disposable vault: each took the
shared Schema's and the vault's instructions, rules, skills and hook, and
followed the knowledge folder's `AGENTS.md`. OpenCode, Pi and Hermes Agent were
not run. Not tried on macOS or Windows.
