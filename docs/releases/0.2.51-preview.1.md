# irori 0.2.51 preview 1 — Codex's file links open or say why

- Codex links each file it names to the file's absolute path, such as
  `[app.py](/abs/path/app.py:12)`. Such a link no longer reaches the browser
  route when the window had not seen its folder: the host looks for the file
  in the vaults, their connected and work folders and the irori agent's folder
  as they are when it is clicked, so a file in a work folder a run just made
  opens on the stage.
- A link to a file outside all of those folders says it was not found and
  which folders irori opens, instead of
  `Error: [ { "code": "custom", … "http または https のリンクだけを開けます。" } ]`.
- A link whose destination is neither a file nor an `http`/`https` address
  (`mailto:`, a folder, `~/…`) keeps its words without being a link that fails.
- A request the host refuses at its boundary reads as the refusal's words
  rather than the validator's issues as JSON.

## Verification

`npm run build`, `npm test` (`tests/links.test.ts`) and `npm run test:ui` pass.
`harness-ui-smoke` replies with Codex's link forms: an absolute path with
spaces in `<…>` opens the file on the stage, a file outside every folder shows
the new message, and a folder link, `mailto:` and `javascript:` are not links.
Not tried with a real Codex run or on macOS or Windows.
