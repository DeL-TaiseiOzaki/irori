## Implemented follow-up

- **Host requests:** [hostArguments](../src/domain/host-requests.ts) validates complete argument tuples. The typed handler registry in [main](../src/host/main.ts) replaces the dispatch switch. Missing schemas/handlers fail type checking. Preload method names are generated from the schema registry by the existing build script; only named methods and event subscription reach the renderer. Sender/frame checks remain in the host. The compiled preload decreased from 3,085 to 1,555 bytes; Zod stays out of the sandboxed preload.
- **Serial operations:** [SerialQueue](../src/host/serial-queue.ts) serves files, workspace profiles and cloud operations. Failed tasks do not poison later work; busy includes waiting work; independent service queues remain independent. Cloud shutdown stops accepting work and drains its queue. Git keeps its existing per-checkout transaction locks and global mutation counter, because they protect a different scope.
- **Device writes:** [local-json](../src/host/local-json.ts) uses `write-file-atomic` for workspace/cloud metadata, scope bindings, agent session handles, drafts and device recovery copies. Parent creation, 0600 files and read-modify-write queues remain. Existing non-regular targets are rejected before the library can follow a symlink. File fsync is enabled. Reviewed document replacement and create-exclusive portable declarations retain their separate logic.
- **Dialogs:** [Dialog](../src/app/Dialog.tsx) shares native modal focus/inert behavior, Escape handling, busy-close guards and focus restoration across Git, cloud connections, registration and new notes. Note creation now also blocks duplicate submissions/closing while its request is pending. Existing layout and draft protection remain.
- **OpenCode SDK:** [OpenCodeServer](../src/agents/opencode.ts) uses the matching official 1.18.30 client for health, sessions, permission/question replies and prompts, with typed events. The SDK is imported only when OpenCode starts, so its ESM-only export works with Electron's CommonJS host. Credentials, redirects, deadlines, session/checkout validation and process-tree ownership stay in irori. Shared `boundedResponse` limits JSON before the SDK buffers it. The SSE parser remains `eventsource-parser` with an explicit header-readiness barrier and no silent reconnection; the SDK's lazy/reconnecting event iterator is not used.
- **Native JSONL:** [JsonLineConnection](../src/agents/json-lines.ts) shares record decoding, correlation, deadlines and pending-request cleanup between Codex and Pi. Their envelopes stay distinct. UTF-8 can split across chunks; records are bounded at 8 MiB before a newline arrives. This removes Codex's reliance on an after-the-line length check. Pi's longer prompt deadline, settled-run behavior and extension dialogs remain.

`write-file-atomic` 8 requires a newer runtime floor than the old `>=24.0.0` declaration. The package now declares `^24.15.0 || >=26.0.0`; development Node 24.21.0 and Electron's Node 24.20.0 satisfy it. [Upstream package and fsync behavior](https://github.com/npm/write-file-atomic)

## ACP evidence and migration decision

A disposable trial used SDK 1.4.0's fluent `client()` API with the installed **OpenCode 1.18.30** `acp` command over stdio. Native state/config/cache directories were isolated, the native side's HTTP listener was bound to loopback with a disposable password, and process trees were stopped afterward. No prompt/model inference or login was sent.

The trial successfully initialized protocol v1, created a session, sent cancellation and loaded the same session from a fresh process. It also attempted loading that handle while specifying a second checkout: **the native ACP endpoint accepted it**. This is evidence that irori must keep its independent session/root validation, not evidence of a model reading or writing the other folder. Source inspection of the pinned OpenCode load path agrees with the observation. [OpenCode ACP command](https://github.com/anomalyco/opencode/blob/v1.18.30/packages/opencode/src/cli/cmd/acp.ts), [session load implementation](https://github.com/anomalyco/opencode/blob/v1.18.30/packages/opencode/src/acp/service.ts)

The examined Pi adapter implements confirm/select but cancels input/editor requests. Claude's adapter supports elicitation and a native executable override, but introducing it would replace the currently pinned SDK and require another compatibility gate. The Codex adapter can select the existing executable via `CODEX_PATH`; it still adds a provider adapter and protocol mapping. None of these observations establishes full native model-turn parity. [Pi adapter](https://github.com/svkozak/pi-acp), [Claude adapter](https://github.com/agentclientprotocol/claude-agent-acp), [Codex adapter](https://github.com/agentclientprotocol/codex-acp)

The final choice is therefore the matching OpenCode HTTP SDK plus shared native JSONL, while retaining Claude's existing official SDK. ACP is not partially enabled behind an untested user-facing switch. Native handles and permission policies are not silently migrated. The app-server decision remains aligned with the [official OpenAI documentation](https://learn.chatgpt.com/docs/app-server).

The trial script, downloaded adapter sources and generated Codex bindings remain ignored under `.local/reuse-audit/`. Sanitized results and source fingerprints are tracked. Those one-shot trials are not shipped regression tests and are not present in a fresh clone.
